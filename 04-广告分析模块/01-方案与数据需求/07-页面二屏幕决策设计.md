# 广告分析模块｜页面二（单一子 ASIN）屏幕决策设计

**性质** 施工单。本轮重构照这份做，实现与它不一致的地方以本文为准。
**要则** 视觉照 `00-通用方法与规范/06-视觉基准要则.md`，参照实现是库存单品盘点页。

---

## 0. 为什么要重构

2026-09-03 王楠看完页面后的判断：「上面的依据非常的冗长，可视化非常的不好，
把每一块都搞成了一坨，根本就没有图表、图标、数据呈现的形式，往下拉根本看不懂。」

对着真页面量过，这三条是事实：

| 现象 | 实测 |
| --- | --- |
| 整页长度 | 1680×**4428px** ≈ 4.2 屏，而四段 Agent 结论**还没展开** |
| 同形状重复 | 「灰框 + chip + 若干 `标签：值` 行 + 依据脚注」重复 **25 次** |
| 图表数量 | **0**。全站唯一的图形是 chip 的圆点 |
| 最大字号的东西 | ASIN 标题。**整页没有一个大数字** |
| 首屏是什么 | 「判断依据」（Agent 的**输入**）占掉页面前 40% |
| 结论在哪 | 四段 Agent 结论默认是空壳，写着「未运行」 |

根因不是排版审美，是**信息架构反了**：把 Agent 的输入放在最上面、最占地方，
把结论放在下面且默认不显示。而每条信息都走 `line(main, 标签, 值)`
渲染成 `标签 + 一段文字`，所以「一坨」是结构性的 —— 想写一句话就得先起一个三五字标签，
想画一个数就没有格子放。

## 1. 页面用户、判断对象、核心问题

**用户** 亚马逊广告运营（吴组长与其下属）。
**判断对象** 一个子 ASIN 在**当前产品目标**与**当前证据**下的广告判断。
**核心问题** 按王楠的原话，这一页是一条链：

```
市场事实  →  本品事实  →  本品判断  →  广告策略建议  →  人审批  →  执行后效果
（外部）     （自己）     （Agent）      （Agent）       （人）      （回灌）
```

前两段是**事实**，Agent 跑之前就存在；第三四段是**Agent 判断**；
第五段是**人的决定**；第六段是**事后事实**。
页面的分节必须等于这条链，一节都不能混。

## 2. 首屏阅读顺序

1. **这个对象现在有几个问题、最急的是哪一类**（决策条上的大数字）
2. **判断能不能作数**（正式判断 / 条件性判断 / 暂时无法判断）
3. **要我做什么**（建议条数与方向）
4. 往下才是为什么

结论先行。板块 ① 与 ② 是事实层，放在判断之后**不对** —— 但事实层是
理解判断的前提，所以顺序仍是事实在前；靠**决策条把结论提到第一屏**解决，
不靠调换板块顺序。

## 3. 六个板块

### 决策条（hero，替代现在的 `ads-ctxbar`）

三栏：身份 / 四个大数字 / 运行与版本。

| 大数字 | 取值 | 档位 |
| --- | --- | --- |
| 本期诊断 | `B3` 条数，脚注写其中 P1 几条 | `--fs-num` |
| 待办建议 | `B4` 条数，脚注写已决定几条 | `--fs-num` |
| 广告对象 | `existing_structure` 个数，脚注写几个共享归因 | `--fs-num` |
| 判断档位 | 正式 / 条件性 / 无法判断 | `--fs-value`（文字型） |

判断档位是文字所以落 22 不落 30（要则第一节的 16/22/30 分界）。

### ① 市场需求与竞争（零判断）

| 组件 | 数据 | 表达的关系 |
| --- | --- | --- |
| **核心词位置图** | `keywords[]` 四词 | 每词一行：词名 · 月搜索量条 · 自然位 `prev→now` 斜线 · 广告位 · 展示份额条 · 覆盖与否（实心/空心） |
| **搜索词份额条** | `ev_*_share.payload.terms[]` 五词 | 份额横条 + 展示位次，按展示量降序 |
| **竞品压力矩阵** | `competitor[]` | 品牌 × 压力类型 小网格，命中格填色，已核实/未核实用形状分 |

**自然位排名越小越好，所以斜线向上代表变好** —— 轴要反向，这是最容易做反的一处。
`mens boxer briefs` 由 7 回落到 9 必须画成向下。

**不画竞品价格带。** 价格只存在于 Agent 写的中文 `detail` 句子里
（「竞品主变体 B086L4BXZC 最终价 21.58 美元」），事实层没有这一列。
从判断产物的文字里正则抽数字再画图 = 把 Agent 的话当数据源，不做。
要画就得让事实层出结构化价格列，那是数据侧的活。

### ② 本品广告事实（零判断）

| 组件 | 数据 | 表达的关系 |
| --- | --- | --- |
| **归因两口径并排** | `existing_structure` 按 `attribution_days` 分桶 | 7 天桶与 14 天桶**各一块，绝不合并** |
| **漏斗** | 每桶 `impressions→clicks→orders` | 三段，转折处标 CTR / CVR |
| **归因稀释条** | `shared_child_count` | 本品在共享桶里占 `1/N`。1192 画出来就是一条几乎看不见的线 |
| **销量六窗口** | `ev_*_trend.payload` | 3/7/14/30/60/90 日均柱。嵌套累计，短窗低于长窗即走低 |
| **库存承接时间轴** | `ev_*_inventory.payload` | 基准日 → 安全线突破 → 压力断货；最晚下单日在过去要标出来 |
| **逐日趋势** | `fact_ad_daily` | 花费柱 + 广告销售额柱 + ACoS 折线（ECharts，比率独立轴 `min:0`） |

**归因两口径必须物理分开。** `ev_*_adperf.payload` 自己把 SP 的 7 天和 SD 的
14 天加成了 `spend: 18792.73 / acos: 0.0755`，而同一条的 caveat 写着
「SP 与 SD/SB 归因窗口不同不可相加」—— 数据自己打自己。页面按窗口分桶显示，
合计只在「两口径不可相加」的说明里出现，不给一个横跨两口径的总数。

**逐日只有一个对象有。** 实测 `camp_79419e721f3f9826` 与 `grp_ed5633a86ba55090`
零逐日行，`grp_300ac8077e33c09e` 有 27 天（48 行 = 两种 `metric_basis`）。
按 `ads.daily_basis` 参数选一种，**不求和** —— 两种口径是两种推导，加起来没有意义。
没有逐日的对象如实说「该对象无逐日记录」，不画空图。

### ③ 本品判断（Agent）

| 组件 | 数据 | 形状 |
| --- | --- | --- |
| **诊断结论带** | `B3` | 照库存 `verdictBand`：优先级点 · 问题名 · 置信度 · 一句话 · ⓘ 展开全文 |
| **诊断覆盖网格** | `B3b` 十类 | 命中的高亮，没命中的给 `why_not`。「查过没发现」也是结论 |
| **目标约束四域** | `B0b` | 成本 / 流量 / 库存 / 事件 四格，硬性 vs 观察，满足状态三态 |
| **结构问题** | `B0e` | 每条挂到广告对象，可点「定位对象」 |

**长文一律收进 ⓘ。** `B3` 的 `what_happened` 实测 300–500 字，
`B0e` 的 `detail` 实测 200–300 字。卡面只给第一句（到第一个句号或 60 字），
全文点开看。这是这次重构最主要的一刀。

**摘句不改写。** 截到第一个句号，不做摘要 —— 摘要是二次判断，
会产出 Agent 没说过的话。截不出句号就按 60 字截并显式带省略号。

### ④ 广告策略建议与审批（Agent + 人）

**会上定的形态**（2026-09-03 王楠原话）：
「我更倾向于说，不是直接执行，而是我把动作、原因、然后预期结果都列出来之后，
给到人，给到人去做审批……判断 AI，我会觉得不要把目前所有的判断都放到 AI 这个链条上，
还是一定是要人去做一层判断才行。」

所以每条建议一张卡，**三栏就叫动作 / 原因 / 预期结果**：

| 栏 | 取值 |
| --- | --- |
| 动作 | `direction_label` 大字 + 作用对象（`ad_object_id` 或结构缺口） |
| 原因 | `rationale` 首句 + ⓘ 全文 + 来自哪条诊断（可点跳回 ③） |
| 预期结果 | `observation_metrics[]` 逐条 + `review_windows[]` 徽标 |

卡底一行：前置条件 N · 风险 N · 不确定项（三个可点标记）+ 审批四按钮
（接受 / 修改后接受 / 拒绝 / 暂缓）。审批后出交接单。

`exact_values_withheld=true` 时明写「规则未确认，只给方向不给数值」，
不留空也不给假数值。

### ⑤ 执行后效果监控（新增）

**会上定的形态**：双阈值 + 到期抓指标 + 达标与否回灌。王楠原话：
「我有两个阈值，第一个就是时间阈值，第二个就是数据量阈值。那我就三天之后，
或者数量达到之后，我就直接去看……如果这个数据他达到了我们的一个目标的话，
那我就判断这个策略是合理的。」

| 组件 | 数据 | 说明 |
| --- | --- | --- |
| **双阈值** | 时间阈值 = `review_windows`；数据量阈值 = 参数 `ads.min_clicks` | 两个阈值都已存在，不新造参数 |
| **效果对比** | `fact_review_feedback.baseline_metrics` vs `observed_metrics` | 十指标逐行：基准值 · 变化幅度双向条 · 观察值 |
| **结论与同期变量** | `conclusion` / `concurrent_variables` / `next_question` | 同期变量必须和结论同屏 |
| **决策事件时间线** | `fact_ad_decision_event` | 接受/修改/拒绝/暂缓 + 交接状态 |

**方向语义必须逐指标定，不能统一。** ACoS 下降是好、CVR 上升是好、
花费上升本身无好坏。给每个指标一个 `better` 方向（`down`/`up`/`neutral`），
`neutral` 的不着色 —— 给花费上升标红是错的判断。

**不声明因果。** 数据自己带着 `concurrent_variables`（bid 变更未知、
自然位未知、促销未知）与 `conclusion`「仅为同期观察，不声明动作导致」。
页面要把这句放在对比图旁边，不能只画一张「改完就好了」的图。

**这份数据只有 `B088WF1PRW` 有**（`fact_review_feedback` 2 行、
`fact_ad_decision_event` 4 行，都挂在它的两个决策版本上）。
五个 ext 对象一条都没有 —— 那五个显示「本对象还没有已执行的建议，无复盘记录」，
**不回落、不构造**。半份结果上屏比空板块更糟（已有两次学费）。

### ⑥ 决策沿革与回测（新增）

| 组件 | 数据 | 说明 |
| --- | --- | --- |
| **版本沿革** | `versions[]` + `previous_decision_id` | 时间轴，可点切到历史版本 |
| **上一版建议后来怎样** | 上一版的 `decision_event` + `review_feedback` | 这是真的「回测」的一种：上次建议的复盘结果 |
| **策略回测** | 无 | **如实标注未接入**，并写清它需要什么 |

**「回测」在会上是两个意思，不要混成一个板块**：

1. 「过了一周之后这个结论……能说明我这个调整到底是 OK 的还是不 OK 的」
   = **效果复盘**。有数据（`fact_review_feedback`），落 ⑤。
2. 「我可以把这个策略带到之前的一个时间点，比如你们这些老品在 2025 年上线的时候，
   我不给他看之后的数据，去看这条策略到底行不行得通」
   = **策略回测**。没有任何数据，也没有 Agent 能力。

第 2 种只画一个空的接入位，写清四个前置条件（选历史基准日、屏蔽该日之后的全部事实、
用同一套门槛跑同一个 Agent、与该日之后的真实结果比），并说明当前缺哪一样。
**不造一条回测结论。**

## 4. 组件与档位

字号只用九档，模块 CSS 里不出现字号字面量，JS 里不出现内联 `font-size`（G20/G23）。

| 组件 | 档位 |
| --- | --- |
| 板块标题 | `--fs-title` |
| 大数字 | `--fs-num` |
| 文字型指标值、日期、复合值 | `--fs-value` |
| 一句话结论 | `--fs-sub` |
| 次级小标题、图例、指标标签 | `--fs-meta` |
| 正文、表格 | `--fs-body` |
| 图上日期标注 | `--fs-anno` |
| 图轴刻度、ⓘ 字形 | `--fs-axis` |

语义色只用四个：`--alert` / `--warn` / `--good` / `--calm`，不新增。
数字列对齐用 `font-variant-numeric: tabular-nums`，**不用 `var(--mono)`**（G22）。
业务页面不用玻璃材质。

## 5. 不做什么

- 不改数据包、不改 Agent 契约、不改外壳文件（`core/`、`shell.js`、`tokens.css`、`base.css`、`index.html`）
- 不改写 Agent 的任何一句话（截首句可以，摘要不可以）
- 不画竞品价格带（事实层无结构化价格列）
- 不给一个横跨 7 天与 14 天归因的合计数
- 不造回测结论、不造复盘记录
- 页面不写库（契约 6.1，`PRAGMA query_only`）

## 6. 可验证的验收标准与实测结果

2026-09-04 实测（同一对象 `B0B3LWGP36`，1680px 视口，`fullPage` 截图）：

| # | 断言 | 结果 |
| --- | --- | --- |
| A1 | 整页高度显著下降 | **没达到**：4428px → 4465px。见下方说明 |
| A2 | 首屏出现结论 | ✅ 决策条四个大数字在第一屏：诊断 2 条（P1 2 条）/ 建议 2 条 / 对象 3 个 / 条件性判断 |
| A3 | 图表数 ≥ 6 | ✅ 实到 9：核心词位置图（含 4 条排名斜线）、份额条、压力矩阵、两个量的链、两条稀释条、六窗口条、库存时间轴、覆盖网格、逐日 ECharts |
| A4 | 七天与十四天归因不出现合计 | ✅ 分两块，并显式写「不可相加，所以这里不给合计数」 |
| A5 | 长文不在卡面 | ✅ 卡面只放首句（截到第一个句号或 76/92 字），全文进 ⓘ |
| A6 | 无复盘记录的对象显示未接入 | ✅ 五个 ext 对象显示「本对象还没有复盘记录」+ 缺什么；`B088WF1PRW` 显示两份真实复盘 |
| A7 | 门禁 25 条全绿 | ✅ 25/25。G24 从「ads 无图表故不适用」变成「ads 已纳入检查且全对」 |
| A8 | 自然位斜线方向 | ✅ `mens boxer briefs` 7→9 画成向下并标橙；`mens underwear` 22→18 向上标绿 |

### A1 为什么没达到，以及为什么不再追

高度几乎没变，但**同一屏里装的东西完全不同**：

- 重构前 4428px 里，四段 Agent 结论是**空壳**（「未运行」占位），
  判断层与建议层一个字都没有；页面前 40% 是 25 个同形状的证据文字框。
- 重构后 4465px 里，判断层 2 条诊断 + 10 类覆盖核对 + 4 域约束 + 3 处结构问题、
  建议层 2 张三栏审批卡、监控层与沿革层两个新板块、9 张图，全部在页面上。

也就是说真实的密度大约是原来的三倍。硬压高度还能做（把六窗口与库存并排已经省了
约 230px，广告对象表从 24 行截到 10 行省了约 340px），但继续压就得开始折叠
判断层与建议层 —— 那正是客户要看的东西，把它折起来是把这次重构的目的挖掉。

**结论：A1 这条断言本身立错了。** 王楠的原话是「往下拉我根本就看不懂」，
说的是看不懂，不是太长。所以验收标准应当换成 A2/A3/A5 那三条（结论是否在首屏、
有没有图、长文是否收起），高度只作为记录不作为门槛。

### 顺带发现并修掉的真 bug

`web/modules/ads.js` 第 450 行一直在调 `downloadExport(...)`，
而这个函数**从来没有被定义过** —— 页面一那个「导出 Excel」按钮点下去只会抛
`ReferenceError`。未定义标识符不是静态错误，只在执行到那一行才抛，所以一直没人发现。
已补在 `web/modules/ads/util.js`（走 `<a download>`，文件名交给后端的
Content-Disposition，不在前端重拼中文名）。

### 需要 Agent 侧改的（本轮不动，页面不改写 Agent 的话）

Agent 写的中文里夹着码值，直接上屏：
`diag_01 判定 KEYWORD_COVERAGE_GAP`、`object_count=2`、`organic_rank`、
`units_recent_14d（1740）`、`covered_by_ad`。
页面只能原样显示 —— 改写它就是产出 Agent 没说过的话。
要治得在 Agent 侧约束输出文案不得含内部标识与英文列名。
