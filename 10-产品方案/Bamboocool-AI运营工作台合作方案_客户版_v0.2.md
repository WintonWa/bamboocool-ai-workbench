# Bamboocool AI 运营工作台 合作方案

**以工作台承载，以 AI Agent 能力为核心，实现 Bamboocool 亚马逊业务的广告运营自动化**

> **合作基础**　以下内容基于已定稿的产品方案（六个模块、十三个业务页面、五十六项能力）与已可运行的工作台 Demo，作为本次合作范围与 Gate 设计的起点。

---

## 01　项目阶段与核心目标

工作台是承载形式，AI Agent 是能力核心。广告运营中原本依赖运营逐个对象人工判断的环节，由 Agent 给出判断与依据，运营确认后执行。

| 阶段 | 这一步要完成什么 | 阶段结束时的决定 |
| --- | --- | --- |
| **Demo 阶段**<br>已完成 | 六个模块的页面结构、判断链与数据口径成形；五个 Agent 已跑通真实模型并落库留档；342 个在售子 ASIN × 730 天真实数据可现场演示。 | 确认页面形态与 Agent 判断形式，作为需求核对的实物基础。 |
| **需求核对** | 逐模块、逐 Agent 与运营核对：哪些判断交给 Agent、哪些留给运营本人；确认阈值首版、数据源责任人与口径；签定开发基线。 | 需求基线冻结，进入开发。 |
| **开发一期**<br>工作台与数据底座 | 数据基建贯通到子 ASIN；六个模块十三个页面的确定性结果全部上屏、可下钻到依据；权限、审计与备份就位。 | 运营可以在工作台上看数、下钻、追溯。 |
| **开发二期**<br>AI Agent 能力接入 | Agent 逐个接入：判断落库、上屏、运行留档、参数可调；运营确认与执行记录闭环。 | 运营可以在工作台上拿到判断，并确认执行。 |
| **验收阶段** | 按量化验收清单逐条核对；Agent 参数交由运营自行调整并验证生效；文档、契约与运行记录交接。 | 进入日常使用，转入迭代。 |

> **核心目标**　把 AI Agent 能力真正用到 Bamboocool 的日常广告运营中，并做到三件事：**每个 Agent 的判断依据可回溯**、**每个 Agent 的门槛参数可由运营自行调整并立刻生效**、**每个 Agent 可迁移**——换站点、换品线、换数据源时，改数据映射与参数即可，不重写判断逻辑。

## 02　三条主线，沿四个 Gate 推进

三条主线在同一节点形成各自的阶段成果。运营工作台负责承载与追溯，AI Agent 负责判断，数据与安全负责让前两条能持续、合规地跑下去。

### 主线一　运营工作台

| Gate | 本主线在这一步完成什么 |
| --- | --- |
| **需求核对** | 十三个业务页面的板块清单与上屏字段逐页确认；筛选、下钻与详情路径确认；总览进入口径确认；确定哪些结果必须可下钻到原始数据。 |
| **开发一期** | 六个模块确定性结果全部上屏：库存覆盖余缺与五类风险、关键词需求覆盖与位置变化、竞品价格活动与流量变化、广告对象归因与区间表现、动作记录与追溯、总览汇总；每个数字可下钻到计算依据、数据版本与统计窗口。 |
| **开发二期** | Agent 判断上屏并与确定性结果并排呈现；Agent 与门槛参数配置页交给运营自己改；Agent 输出记录页可逐条回看历史运行。 |
| **验收上线** | 总览结论与周报草稿；页面上下文问答；四位运营各自完成一轮真实使用并提出修改清单。 |

### 主线二　AI Agent

| Gate | 本主线在这一步完成什么 |
| --- | --- |
| **需求核对** | 逐个 Agent 与运营核对三件事：它替运营判断什么、它不判断什么（留给运营）、它受哪些门槛参数约束；确认每个 Agent 的输入表、输出列与禁读清单；确认"证据不足"时的上屏说法。 |
| **开发一期** | Agent 运行框架建成：调用、落库、留档、参数读取与运行台账；判断结果与确定性数字的交叉核对机制建成；首批 Agent 接入并跑通。 |
| **开发二期** | 约定范围内的 Agent 全部接入：判断落库、上屏、可点开查看执行过程与使用的数据源；每个 Agent 的门槛参数在配置页可改并立刻重算；运营的接受、修改、拒绝、暂缓可记录并追溯。 |
| **验收上线** | 每个 Agent 逐条验收：判断可追溯、参数可调、契约可读、运行留档；运营自行调整参数并验证结论随之变化；Agent 契约与提示词版本交接。 |

### 主线三　数据与安全

| Gate | 本主线在这一步完成什么 |
| --- | --- |
| **需求核对** | 数据源清单与责任人确认；各源的统计周期、时区、货币与广告归因口径确认；现有报表导出方式与频率确认；数据缺口登记并标注责任人与时间。 |
| **开发一期** | 客户自有云账号内建成接入层：原件只读保存、校验、字段映射、去重与版本记录；对象关系贯通到子 ASIN；权限分级、操作审计、加密与备份验证通过。 |
| **开发二期** | 模型安全网关就位：按当前任务提取字段、去除凭证与无关内容后调用客户批准的模型；模型结果写回并记录数据版本与模型版本；不覆盖原始数据、规则计算与运营已确认的决定。 |
| **验收上线** | 接口化路径评估（哪些源可从人工上传切为定时读取）；写回外部系统的执行通道与确认流程；账号、密钥与运维交接。 |

> **工作重心**　AI Agent 是能力核心，但它依赖确定性结果作为输入，因此开发一期先把数据底座与确定性计算做实，开发二期集中接入 Agent。Agent 逐个接入、逐个验收，不等全部模块完成再统一开始。服务期自 Kickoff 起算，预计 【待定】 周；合同签署至 Kickoff 准备约 1–2 周。执行与复盘的 D+3 / D+7 结果积累需要运营真实执行后才能形成，列为下一阶段建议。

## 03　交付物

### 3.1　AI Agent 能力

九个 Agent 已完成能力定义，覆盖五个模块。每个 Agent 都明确划分了"它判断什么"与"什么留给确定性计算"——预测、归因、影响幅度与中文理由由 Agent 产出；覆盖天数、断货日、缺口量、计数与占比等算术留在工作台，因为门槛参数一改就要立刻重算。

| AI Agent | 所属模块 | 它替运营判断什么 | 判断点 | 可调参数 |
| --- | --- | --- | --- | --- |
| **需求预测** | 产品与库存 | 真实需求是多少，产出未来 90 天逐日预测与区间；历史销量有没有被缺货扭曲、活动影响多大、生命周期在哪一段 | 3 | 5 |
| **盘点结论** | 产品与库存 | 这个对象当下该不该动、动什么；两个口径同时为真时该怎么说；五条结论里哪条最要紧 | 4 | 4 |
| **库存总体分析** | 产品与库存 | 一个分组里哪几个对象是重点，整体处在什么状态 | 2 | 7 |
| **关键词机会与风险** | 关键词分析 | 从词级位置变化里挑出值得动的词，并给优先级 | 6 | 7 |
| **子体关键词布局** | 关键词分析 | 给定当前推广目标，这个子体的词该怎么排布、缺哪些词、该推哪个 | 3 | 2 |
| **竞品威胁判定** | 竞品分析 | 竞品降价、排名与关键词位置变化中，哪些构成真威胁 | 4 | 7 |
| **广告异常与决策** | 广告分析 | 四类异常里哪些该调价、哪些该扩量、哪些只是样本不够 | 5 | 11 |
| **广告目的标签** | 广告分析 | 从命名、结构与投放行为里判断一个广告对象到底在干什么，补上认不出来的那些 | 2 | 3 |
| **运营总览** | 运营总览 | 读完四个模块的结论后，写出本周期的总览结论与重点顺序 | 5 | 【待定】 |
| **其他满足业务需求所需的 Agent** | 按需 | 需求核对阶段与运营共同确认后新增，例如执行复盘结论、毛利与广告消耗测算、新品测算等 | 待定 | 待定 |

**每个 Agent 交付时都带四样东西**，这也是"可调参数、可迁移"的落地形式：

- **接口契约**｜读哪些表、禁读哪些表、输出哪些列，逐字写明。换数据源时改映射即可，判断逻辑不动。
- **门槛参数声明**｜它受哪几个参数约束（当前九个 Agent 共声明 34 个参数键），参数在配置页可改并立刻重算。
- **判断与算术的边界**｜哪些是 Agent 判断、哪些是工作台计算，写在同一份声明里，避免同一个数字有两个来源。
- **运行留档**｜每次运行记录时间、对象、模型版本、数据口径、执行过程与结论，可逐条回看。

### 3.2　运营工作台

六个模块、十三个业务页面：运营总览 1 页、产品与库存 3 页、关键词分析 3 页、竞品分析 2 页、广告分析 2 页、执行与复盘 2 页。共五十六项能力，含跨模块对象关系与三类必须保留的边界（广告归因边界、同期变化与因果的区分、多统计周期并列不强行统一）。

### 3.3　数据与文档

- 数据基建：对象关系、原始表、业务过程表、历史快照表、规则配置表与模块结果表，全部在客户自有云账号内。
- 口径台账：各数据源的统计周期、时区、货币与归因口径；数据缺口登记（含影响范围、责任人与时间）。
- 阈值与规则台账：客户确认的参数版本与修改记录。
- Agent 契约与提示词版本；运行记录与决策记录。

- **会议节奏**｜开发一期 Gate 前每周 45 分钟，之后双周 60 分钟；以远程协作为主，每次更新聚焦完成项、风险依赖、待决策事项与下一步。

| **范围变更** | 驻场、额外会议、新增模块与新增数据源，通过 Change Order / SOW 另行确认。 |

## 06　付款 Gate 与量化验收

### Gate 1｜合同签署与需求核对｜30%

- **商务触发**：合同生效，首期款按合同约定支付。
- **项目接口**：业务拍板人、运营负责人、数据负责人、系统 / IT 负责人共 4 类责任书面确认；可由同一人员兼任。
- **需求基线**：十三个业务页面的板块与上屏字段逐页确认并冻结；变更走 Change Order。
- **Agent 范围**：九个已定义 Agent 逐个与运营核对"判断什么 / 不判断什么 / 受哪些参数约束"，并确认本期接入范围与新增 Agent 清单。
- **阈值首版**：安全库存天数、库龄档位、超量判据、ACOS 与异常判据等参数由客户确认首版，并约定后续修改方式。
- **启动资料**：产品关系、报表导出、广告结构与排期资料进入统一清单；缺失项 100% 标注责任人与预计时间。
- **Gate 文件**：提交 1 份需求核对 Gate Memo，明确 Proceed / Refine / Pivot / Stop 之一。

> **数据缺口不阻塞**　客户数据源本身缺失或口径未定时，该项进入数据缺口登记（标注影响范围、责任人与预计时间），其余工作继续，时间按实际依赖顺延。已识别的缺口在本 Gate 明确列出，不留到后期发现。

### Gate 2｜开发一期：工作台与数据底座｜25%

- **对象关系贯通**：任取 1 个子 ASIN，可完整找到与它相关的库存、关键词、竞品、广告与动作数据，每项数据明确来源与更新时间。
- **数据接入覆盖**：销售、库存与物流、补货、关键词、竞品、广告共 6 类数据完成导入、校验与版本记录；字段缺失、重复与映射冲突 100% 留在待处理状态而非静默通过。
- **页面覆盖**：六个模块十三个业务页面全部上线，确定性结果使用真实数据稳定生成。
- **结果可追溯**：每个上屏结果 100% 可下钻到计算依据与来源数据，包含数据版本与统计窗口。
- **机械门禁**：每个模块交付时跑一次门禁清单（当前 24 条，覆盖路由隔离、只读约束、参数口径、视觉基准、Agent 声明交叉引用），条数与逐条结果写进 Gate 文件。
- **数据安全就位**：权限分级、操作审计、加密与备份完成验证。
- **Gate 文件**：提交 1 份开发一期 Gate Memo。

### Gate 3｜开发二期：AI Agent 能力接入｜25%

- **Agent 覆盖**：本期约定的 Agent 全部接入，每条结论可说明使用了哪些标准结果、为什么形成该判断、缺少什么信息。
- **数字一致**：Agent 引用的每个数字与确定性计算层同口径交叉核对，不一致的运行不入库、不上屏。
- **参数可调**：每个 Agent 声明的门槛参数在配置页可改并立刻重算；改一个参数，受它影响的结论随之变化且可复现。
- **运行留档**：全部运行 100% 进入统一记录，包含时间、对象、模型版本、数据口径、执行过程与结论，失败运行同样留档并说明原因。
- **模型边界**：模型不直接接触数据库与原始文件；输入字段与输出结果逐次记录数据版本与模型版本。
- **确认闭环**：运营接受、修改后接受、拒绝或暂缓的决定，以及实际执行的对象、动作、数值与时间可完整追溯。
- **Gate 文件**：提交 1 份开发二期 Gate Memo。

### Gate 4｜验收与交接｜20%

- **逐条验收**：按量化验收清单逐条核对并签署；未通过项形成关闭、降级、延期或不进入本期承诺的明确结论。
- **运营自验**：四位运营各自完成一轮真实使用，自行调整至少 1 个 Agent 的门槛参数并验证结论随之变化。
- **可迁移验证**：任取 1 个 Agent，说明换站点或换品线时需要改哪些映射与参数、不需要改哪些判断逻辑。
- **最终交付**：验收 Gate Memo、总览结论与周报草稿、阈值与规则台账、Agent 契约与提示词版本、运行记录与决策记录、云账号与运维交接、后续 90 天行动建议。

> **有效验收**　Agent 给出"证据不足""数据不足以判断"或建议暂缓，同样算完成了这一步。验收看的是判断依据是否完整、是否可追溯、缺口是否说清，**不要求 Agent 得出预设的正面结论**。一条把不确定性说清楚的结论，比一条看上去果断但无法回溯的结论更符合验收标准。
