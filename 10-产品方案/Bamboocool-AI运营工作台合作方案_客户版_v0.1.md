# Bamboocool AI 运营工作台 合作方案

**以「产品与库存 → 关键词 → 竞品 → 广告决策」这条判断链为当前主轴，同步推进判断层与数据接入**

> **合作基础**　以下内容基于已完成的产品方案（六个模块、十三个业务页面、五十六项能力）与已可运行的工作台原型，作为本次合作范围与 Gate 设计的起点。

---

## 01　当前阶段与合作目标

| 当前阶段 | 本项目将共同完成的决定 |
| --- | --- |

## 02　三条主线，沿四个 Gate 推进

从左到右依次完成四个 Gate；三条主线在同一节点形成各自的阶段成果，并把运营的真实反馈写回规则与判断层。

| 时间轴 →<br>工作主线 ↓ | **01 →**<br>启动与口径对齐<br>约 1–2 周｜30% | **02 →**<br>数据与口径 Gate<br>Kickoff 后第 【待定】 周｜25% | **03 →**<br>工作台上线 Gate<br>Kickoff 后第 【待定】 周｜25% | **04**<br>判断层 Gate<br>Kickoff 后第 【待定】 周｜20% |
| --- | --- | --- | --- | --- |
| **运营工作台**<br>六模块十三页 | 页面基线与优先模块 | 对象关系与数据状态可查 | 六模块确定性结果全部上屏、可下钻到依据 | 总览结论与周报草稿 |
| **判断层**<br>逐例判断与证据 | 判断点清单与红线 | 输入输出契约、禁读清单 | 首批判断点接入并留档 | 判断点全量接入、运营确认闭环 |
| **数据与安全**<br>客户自有云 | 数据源清单与责任人 | 接入、校验与版本机制建成 | 权限、审计与备份就位 | 接口化路径与交接 |

> **工作重心**　运营工作台是本期主交付轴；判断层随模块逐个接入，不等全部模块完成再统一开始；数据与安全全程在客户自有云账号内完成。服务期自 Kickoff 起算，预计 【待定】 周；合同签署至 Kickoff 准备约 1–2 周。执行与复盘模块（D+3 / D+7）需要运营真实执行后才能积累结果，列为下一阶段建议。

## 04　专属项目组与协作机制

**配置 【待定】 人专属项目组，持续推进三条主线与四个 Gate**

| 项目角色 | 负责内容 |
| --- | --- |
| **【待定】**<br>产品与判断负责人 | 负责判断口径、能力清单落地与 Gate 判断，并提出页面、阈值与判断层建议。 |
| **【待定】**<br>工程负责人 | 负责数据基建、确定性计算、工作台实现与验收门禁。 |
| **【待定】**<br>客户接口与项目推进 | 负责会议机制、时间表、风险依赖与资料缺口跟进。 |
| **Bamboocool 核心接口** | 确认业务优先级、阈值与数据责任；提供运营、数据与系统接口；完成关键 Gate 决策。 |

**协作方式**

- **工作闭环**｜运营在页面上的反馈按周进入规则台账与开发任务，形成阈值与提示词的修改依据。
- **验收前置**｜每个模块交付时先跑一次机械门禁清单，条数与结果写进 Gate 文件，不靠人工抽查。
- **会议节奏**｜工作台上线 Gate 前每周 45 分钟，之后双周 60 分钟；以远程协作为主，每次更新聚焦完成项、风险依赖、待决策事项与下一步。

**数据、保密与变更**

| 事项 | 合作约定 |
| --- | --- |
| **部署与归属** | 采用客户自有云账号：数据库、对象存储、密钥与备份全部在 Bamboocool 名下。我方负责部署与维护，客户始终掌握数据与云资源。维护权限由客户临时授予，到期自动收回。 |
| **原始数据** | 上传的报表原件只读保存在客户对象存储中，记录来源、批次与文件哈希。新数据形成新版本，不覆盖已生成的历史判断与报告。 |
| **模型使用** | 外部大模型不直接连接数据库或浏览客户文件。由安全网关按当前任务提取所需字段，去除凭证与无关内容后调用客户批准的模型服务；返回结果写回客户数据库并记录数据版本与模型版本。模型结果不覆盖原始数据、规则计算和运营已确认的决定。 |
| **权限与审计** | 客户使用自有企业身份登录并启用多因素认证；上传、查看、导出、配置修改、模型调用与系统写回全部留操作记录。数据库位于私有网络，不对公网开放。 |
| **写回外部系统** | 需要向 Amazon、领星或飞书写回时，由独立执行通道处理：运营先确认对象与数值，系统再提交，并保存执行前值、目标值与外部返回结果。 |
| **保密** | 不向引荐方或第三方披露产品资料、经营数据、关键词与竞品研究过程及过程性商业信息。 |
| **范围变更** | 驻场、额外会议、新增模块与新增数据源，通过 Change Order / SOW 另行确认。 |

> **下一步**　双方确认合作范围与商务条款后，进入合同签署、首期款与 Kickoff 准备。

## 05　付款 Gate 与量化验收

### Gate 0｜合同签署与启动｜30%｜准备约 1–2 周

- **商务触发**：合同生效，首期款按合同约定支付。
- **项目接口**：业务拍板人、运营负责人、数据负责人、系统 / IT 负责人共 4 类责任书面确认；可由同一人员兼任。
- **启动资料**：产品关系、报表导出、阈值现状、广告结构与排期资料进入统一清单；缺失项 100% 标注责任人与预计时间。
- **启动机制**：完成 1 次 Kickoff，确认开发基线、Master Timeline、Gate 日历、会议机制与变更流程。

### Gate 1｜数据与口径 Gate｜25%｜Kickoff 后第 【待定】 周

- **对象关系贯通**：任取 1 个子 ASIN，可完整找到与它相关的库存、关键词、竞品、广告与动作数据，每项数据明确来源与更新时间。
- **数据接入覆盖**：销售、库存与物流、补货、关键词、竞品、广告共 6 类数据完成导入、校验与版本记录；字段缺失、重复与映射冲突 100% 留在待处理状态而非静默通过。
- **口径确认**：日、周、30 天、月度与活动周期各自保留正式统计口径；共享或混合多个子 ASIN 的广告对象保留归因边界。
- **阈值首版**：安全库存天数、库龄档位、超量判据、异常判据等参数由客户确认首版，并约定后续修改方式。
- **判断层契约**：判断点清单、每个判断点的输入表、禁读清单与输出列定稿，两侧逐字一致。
- **Gate 文件**：提交 1 份数据与口径 Gate Memo，明确 Proceed / Refine / Pivot / Stop 之一。

> **数据缺口不阻塞**　客户数据源本身缺失或口径未定时，该项进入数据缺口登记（标注影响范围、责任人与预计时间），其余工作继续，时间按实际依赖顺延。已识别的缺口在本 Gate 明确列出，不留到后期发现。

### Gate 2｜工作台上线 Gate｜25%｜Kickoff 后第 【待定】 周

- **页面覆盖**：六个模块十三个业务页面全部上线，确定性结果使用真实数据稳定生成。
- **结果可追溯**：每个上屏结果 100% 可下钻到计算依据与来源数据，包含数据版本与统计窗口。
- **机械门禁**：每个模块交付时跑一次门禁清单（当前 24 条，覆盖路由隔离、只读约束、参数口径、视觉基准、Agent 声明交叉引用），条数与逐条结果写进 Gate 文件。
- **首批判断点**：约定数量的判断点接入并留档，每次运行可点开查看执行过程、使用的数据源、耗时与结论。
- **数据安全就位**：权限分级、操作审计、加密与备份完成验证。
- **Gate 文件**：提交 1 份工作台上线 Gate Memo。

### Gate 3｜判断层 Gate｜20%｜Kickoff 后第 【待定】 周

- **判断点覆盖**：约定的判断点全部接入，每条结论可说明使用了哪些标准结果、为什么形成该判断、缺少什么信息。
- **数字一致**：判断层引用的每个数字与确定性计算层同口径交叉核对，不一致的运行不入库、不上屏。
- **运行留档**：全部运行 100% 进入统一记录，包含时间、对象、模型版本、数据口径、执行过程与结论。
- **确认闭环**：运营接受、修改后接受、拒绝或暂缓的决定，以及实际执行的对象、动作、数值与时间可完整追溯。
- **最终交付**：判断层 Gate Memo、总览结论与周报草稿、阈值与规则台账、运行记录与决策记录交接、后续 90 天行动建议。

> **有效验收**　判断层给出"证据不足""数据不足以判断"或建议暂缓，同样算完成了这一步。验收看的是判断依据是否完整、是否可追溯、缺口是否说清，**不要求系统得出预设的正面结论**。一条把不确定性说清楚的结论，比一条看上去果断但无法回溯的结论更符合验收标准。
