工作流程

从进场到部署，七个环节按顺序推进。前两步是梳理，把数据和判断逻辑摸清；后五步是建设，逐步把判断交给 Agent。

01
梳理数据
数据源、口径、对象关系摸清，贯通到子 ASIN
02
梳理业务
逐个环节定：哪些判断交给 Agent，哪些留给运营
03
建立 Agent
按业务逻辑逐个建，判断落库、上屏、留档
04
调 Agent
门槛参数与判断方法论持续校准，越跑越准
05
建立前端框架
Agent 的判断有承接的地方，运营能看、能下钻、能改
06
模型微调
用积累的判断与反馈微调模型，沉淀成公司自己的能力
07
部署
上线运行，权限、审计与运维交接
05

问题

日常运营面对的判断量，靠人一个一个看根本看不过来。

1,500+
个 ASIN 的仓储情况需要盘清楚
90 天
的面料预投数量需要算出来
逐个定策略
不同库存状态的产品，需要不同的运营动作

比如：

  • 快断货的产品 → 减少推广力度，减少广告投入，避免卖空
  • 库存积压、已经产生仓储费的产品 → 匹配更激进的投放策略，加速出清
  • 面料预投 → 57 个配色组各投多少，投多了压资金，投少了断货

每个产品情况不一样，策略也不一样。靠人一个一个判断，既慢又不一致。

这就是 Agent 解决的事

一个 Agent 看全部

不管是 100 个还是 1,500 个 ASIN，同一个 Agent 用同一套标准逐个过，不会遗漏、不会偏。

判断质量可沉淀

把已有的判断经验写进 Agent 的规则里，新人来了也是同一套标准。判断方法越用越准，不会因为人员变动丢掉。

单品盘点

  • 库存承接（可售余额、在途到货、安全线、预计断货日）
  • 风险判定（库存不足、超量备货、可用性异常）
  • 库龄分布与仓储费估算

面料预投

管的是钱出去之前——这一轮面料投多少。判断对象是配色组（款号 × 组合），共 57 个。时间口径 M+2：8 月做的预投对应 10 月销量。考核标准：下单数 ÷ 预投数 ≥ 70%。

预投计划
替代运营填 Excel 的动作，在线填、在线改、直接导出
  • 57 个配色组分两堆：需要复核的 + 按建议走的
  • 每行标出为什么要复核（上轮投偏、下月有活动、款在爬坡）
  • 预估销量区间（P10–P90）
  • 系统建议盒数 + 可修改的「我要投」输入框
  • 实时折算面料吨数
  • 导出预投表交生产端
配色组依据
某一行的建议值该接受还是该改，把黑盒打开
  • 决策条：系统建议 → 我最终投 → 折面料
  • 逐日柱状图：历史实销 + AI 预估，销售月高亮标出
  • Agent 判断摘要（生命周期、近期表现、活动影响、季节因素）
  • 三样反驳证据：去年同期、上一轮达成率、下月活动
  • 尺码拆分（生产端按它拆条）
Agent
需求预测 Agent（复用）
预投复用库存模块的需求预测结果。AI 已经对每个子体做了未来 90 天的销量预估，这里按配色组聚合后加上安全余量，就是预投建议值。不重复跑一遍预测。

权限管理

不同角色配备不同权限，看到的数据和能做的操作不一样。两个方案下都一样。

权限项说明
页面访问权限不同人能进不同模块——比如运营能看库存和广告，财务只能看库存和仓储费
数据查看权限控制每个人能看到哪些数据范围（按店铺、按负责人、按产品线）
导出权限只有被授权的人才能导出 Excel 和预投表
输入/修改权限预投表的「我要投」、广告决策的「接受/修改」，需要对应权限才能操作
Agent 配置权限门槛参数的调整、配置方案的切换，仅管理员可操作
