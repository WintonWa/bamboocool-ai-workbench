# 关键词分析页 · 承载体设计

**性质** 这是**设计决定**，不是施工记录。重构照这份做，后续改动也照这份判。
**日期** 2026-09-04
**起因** 王楠：「它是一个草稿，像一个书写的人把信息都给撸了起来，完全没有一点逻辑的
视觉重现的重点、先后顺序。」「你要知道真实的生产过程中，不太可能给你这样的设计空间，
说你想有多少空间就这么设计。你肯定是有一个可承载的载体，然后再去承载你的信息。
而这个载体一定是有它的一个固定的形式。」

---

## 一、诊断：缺的不是图，是槽位

我们给 Agent 定了**输入输出契约**（读哪些表、写哪些列），但没给它的产出定
**上屏契约**。于是 Agent 写多少字，页面就铺多少字。

一条证据现在长这样，四行自由文字：

```
[核心位置风险] 32 cool mens underwear   [证据完整] [进入竞品分析验证]
核心词「32 cool mens underwear」上，B0B3LWGP36 的位置正在走弱          ← conclusion
B0B3LWGP36 在「32 cool mens underwear」的自然位从第 1 位降到第 10 位   ← main_basis
库存限制：不可承接扩量                                                ← 可选
```

子体盘点页一次铺 36 条 = **144 行**，其中 13 条是同一类，文案模板一致。
这就是「一坨」。三个具体病灶：

| 病灶 | 现状 | 后果 |
| --- | --- | --- |
| **文字没有空间预算** | conclusion / main_basis 任意长度直接进正文 | 长句撑破节奏，短句留白，同类刷屏 |
| **同类证据逐条平铺** | 13 条核心位置风险 = 13 个同构文字块 | 读第三条起就不再读了 |
| **判据只有文字没有形状** | 「从第 1 位降到第 10 位」只是一句话 | 9 位和 90 位的跌幅看着一样重 |

表格的病同源：19 行 × 9 列全是数字，**没有一列承担"排序"以外的视觉职责**。

## 二、三层承载体

### 第一层 · 页面骨架：四段固定顺序

每一页同一个骨架，换页不用重新学：

| 段 | 回答什么 | 允许的内容 | 允许的高度 |
| --- | --- | --- | --- |
| ① **来源** | 这一屏可不可信、谁判的 | 判断来源条（已有，压薄成一行） | 1 行 |
| ② **结论** | 这一页的问题的答案 | 主数字 + ≤4 支撑格 + ≤5 条结论行 | ≤ 一屏 |
| ③ **证据** | 凭什么这么说 | 板块，每块 = 指标条 + **一张图** + 一张表 | 不限 |
| ④ **追溯** | 口径、历史、原始记录 | 折叠区，默认收起 | 0（收起） |

现状问题：②③ 混在一起，④ 不存在（口径说明散在正文里）。

### 第二层 · 板块骨架：一图一表，图在表前

**每个板块必须有一张图。** 没有图的板块说明这块的问题没被想清楚 ——
表格是"给我看全部"，图是"告诉我该看哪个"，缺图就等于没有先后顺序。

```
板块标题  [AI徽标] [方案下拉] [导出]
指标条：≤5 格，每格 = 标签 + 值（+ 语义色）        ← 眼睛第一落点
图：回答"该看哪个"                                 ← 第二落点
表：回答"全部长什么样"，可排序                     ← 第三落点，可滚动
口径 ⓘ：收进浮层，不占正文行                       ← 点开才有
```

口径说明**不留在正文**。库存页已经这么做（`info()` 浮层），关键词页现在把口径
写成 `kw-sec-note` 灰字行，每块一到两行，累计十几行纯说明文字。

### 第三层 · Agent 文字的承载体（本次核心）

#### 3.1 证据组（evidence group）——同类不再平铺

**一类证据 = 一个组，不是 N 个卡。**

```
┌ 组头 ───────────────────────────────────────────────┐
│ [核心位置风险] 13 条   ▓▓▓▓▓▓░░░░ 严重度分布         │  ← 组头带该类的构成图形
├ 行 ─────────────────────────────────────────────────┤
│ ●━━━━━━━○      32 cool mens underwear   第1→10位  ⓘ │  ← 一行一条，图形在最左
│ ●━━━━○         bamboo boxer briefs men  第1→3位   ⓘ │
│ ●━━━━━━━━━━○   bamboo boxers for men    第1→10位  ⓘ │
│ 另有 10 条，展开                                     │
└─────────────────────────────────────────────────────┘
```

组内每行**五槽固定**，每槽有空间预算，超了就降级而不是换行：

| 槽 | 内容来源 | 形式 | 宽度 | 溢出处理 |
| --- | --- | --- | --- | --- |
| S1 **判据图形** | 从 main_basis 的数字抽出 | 位次游标 / 幅度条 / 方向箭头 | 定宽 96px | 图形不溢出 |
| S2 **对象** | keyword | 单行，加粗 | 弹性，min 0 | `text-overflow: ellipsis` |
| S3 **量** | 变化的数值 | 数字，tabular-nums | 定宽 | 无 |
| S4 **状态** | 完整度 / 下一步 / 库存约束 | 定宽标签组，固定三槽 | 定宽 | 缺项留空不塌陷 |
| S5 **详情** | conclusion + main_basis + 引用事件 | **ⓘ 浮层** | 16px | 全部在浮层内 |

**关键决定：`main_basis` 不上卡面。**
它是 conclusion 的数字版重述，两行并排既重复又是「一坨」的主要来源。
它进 S1 的图形（数字部分）和 S5 的浮层（完整句子）。

**次要决定：conclusion 只在组头出现一次的"共性判断"里出整句**，
组内行只出 S3 的量。同一类 13 条的 conclusion 只在措辞上差一个关键词名，
逐条重复 13 遍等于让人读 13 遍同一句话。

#### 3.2 结论行（verdict row）——照搬库存页已验证的形状

页面级结论（②段）用库存页 `verdictBand` 的同一形状，不另发明：

```
● 名称        状态词      一句话结论                              ⓘ
```

固定四槽：状态点（颜色）+ 名称（定宽）+ 状态词（定宽）+ 结论句（`--fs-sub`，单行）。
**结论句限一行**，写不下就是结论没提炼够，不给它换行的权利。

#### 3.3 表格的可视化职责分配

一张表里**每一列只能承担一种职责**，且至少一列必须是图形：

| 职责 | 形式 | 关键词页用在哪 |
| --- | --- | --- |
| 身份 | 文字，可点 | 关键词 / 子ASIN / 词组名 |
| 量级 | **条形 + 数字**（条在数字后，右对齐） | 月搜索量、缺口、涉及词数 |
| 占比 | **热力格**（背景浓度 = 值） | 组内覆盖率、自然覆盖率 |
| 位置 | **区间游标**（轨道 + 点） | 位次区间、当前自然位 |
| 趋势 | **迷你折线**（不是柱） | 90 天位次轨迹 |
| 方向 | 箭头 + 数字，语义色 | 净变化、位次变动 |
| 分类 | 文字标签 | 维度、角色、状态 |

**禁止**：一张表里超过 6 列纯数字。超了就说明这张表在替代图，把最重要的两三列
提成图，其余收进"展开全部列"。

## 三、逐页设计

### 页面一 · 关键词动态与机会总览

| 段 | 板块 | 图 | 变化 |
| --- | --- | --- | --- |
| ① | 判断来源条 | — | 压成一行 |
| ② | **今天该看什么** | 14 天流量迷你趋势 | 五问五答**改成**主数字 + 4 支撑格 + 5 条结论行（每行单行） |
| ③ | 市场需求与词组变化 | **词组变化条形图**（上涨/下滑双向） | 表从 9 列压到 6 列 + 量级条 |
| ③ | 自有核心词覆盖与位置变化 | **位次变化散点图**（x=从，y=到，偏离对角线=变化幅度） | 表按子体分组，位次变化画成游标 |
| ③ | 关键词机会、缺口与风险 | 类型构成堆叠条（保留） | **改证据组**：5 组头 + 行式，main_basis 进浮层 |
| ④ | 数据范围与口径 | — | **从正文第二块移到页尾折叠** |

「数据范围与数据状态」现在排在第二位，占一整块讲词库有多少个词 ——
那是**上下文不是结论**，挡在读者和真正的结论之间。移到页尾折叠。

### 页面二 · 市场关键词库与单词深研

**词库列表**

| 段 | 板块 | 图 |
| --- | --- | --- |
| ② | 词库规模与质量 | 状态构成堆叠条（替换两排 chips） |
| ③ | 需求词组与市场结构 | **词组气泡/条形**：搜索量 × 词数 |
| ③ | 市场关键词比较区 | **散点图**：月搜索量 × 需供比，点大小=在售商品数 |

比较区那张 200 行 × 10 列表是最典型的"数据罗列"。加一张散点图回答
「哪些词是高需求低竞争」，表退成明细。

**单词深研**

| 段 | 板块 | 图 |
| --- | --- | --- |
| ② | 词身份与规模 | — （主数字 + 支撑格 + 标签组） |
| ③ | 双频率市场事实 | **ECharts 双轴图**（替换 CSS 柱），月/周各一张 |
| ③ | 两来源同期数值 | **哑铃图**（两点一线，线长=分歧幅度） |
| ③ | 头部 ASIN 与竞品线索 | **点击占比条形**（前三名）+ 第一名更替时间线 |
| ③ | 关键词与产品关系 | 位次游标列 |
| ④ | 同义变体 / 所属词组 / 类目 | 折叠 |

「两来源冲突」现在是四列表格加"一致/不一致"文字。**哑铃图**是这件事的标准画法：
两个点 + 一条线，线长就是分歧幅度，一眼看出哪个指标分歧最大。

## 四、不做的事

- **不改后端载荷字段。** 这次是承载体设计，`compute.py` 的输出结构不动。
  唯一例外：证据行需要的"数字部分"若无法从现有字段取到，也不在后端解析文本 ——
  取不到就退化成只显示状态标签，不猜。
- **不新增字号档位、不新增色值。** 九档字号 + 五个语义色够用，G3/G19-G23 守着。
- **不引第三方图表库。** ECharts 已在 `/assets/echarts.min.js`，库存与竞品共用一份。
- **不动 Agent 判什么。** conclusion / main_basis 的文字仍由 Agent 产出，
  本设计只规定它们**上屏时落在哪个槽、有多少空间、超了怎么降级**。

## 五、验收

| 项 | 判据 |
| --- | --- |
| 每个板块有图 | 三页所有 `sec()` 板块，图数 ≥ 1（追溯段折叠区除外） |
| 无自由生长文字 | 正文里不出现连续两行以上的 Agent 原句；`main_basis` 只在浮层 |
| 表格列数 | 单表纯数字列 ≤ 6 |
| 门禁 | 25/25 全绿（尤其 G20 无字号字面量、G23 JS 无内联字号、G24 图表字号镜像） |
| 视觉 | 逐页截图人工看过，四个视图各一张 |
