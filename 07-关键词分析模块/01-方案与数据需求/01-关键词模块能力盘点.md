# 关键词分析模块 — 架构需要的能力盘点

> 依据：`Bamboocool-AI运营工作台方案.md` 4.3 / 5.2 / 7.3（全节）/ 8.3（全节）
> 盘点日期：2026-08-30　　对应数据基准日：2026-08-03

---

## 0. 一句话结论

三个页面共用一条能力链，链条只有一个方向：

```text
市场词库 → 分类与词组 → 市场事实 → 市场变化
                                    ↘
关键词 × 子ASIN 覆盖位置 → 覆盖变化 → 绑定产品目标与库存 → 机会/缺口/风险/待验证 → 总览·深研·盘点·下游交接
```

十项纵向能力里，**六项半是确定性算子和数据基建，三项半才是真判断层**。判断层集中在“词与产品匹配”“证据定性”“日报叙述”三处；页面能不能立住，取决于横切的六条一致性约束，而不是取决于板块多少。

## 1. 架构骨架：三页 × 三层对象

| 页面 | 服务的任务 | 组织方式 | 输出的对象层 |
| --- | --- | --- | --- |
| 页面一 关键词动态与机会总览 | 今天发生了什么、先看哪里 | 按变化重要性 | 日报 + 优先事项列表 |
| 页面二 市场关键词库与单词深研 | 市场有哪些词、一个词意味着什么 | 按关键词本身 | 市场事实 + 绑定后的产品关系证据 |
| 页面三 子 ASIN 关键词盘点 | 一个产品覆盖了什么、缺什么 | 按产品 | 标准化产品级关键词结果 |

三层业务对象（三页共用，不重复建）：

1. **市场关键词**（市场事实层）— 未绑产品时只能说市场事实，不能判断值不值得投；
2. **关键词 × 子 ASIN**（产品关系层）— 覆盖与位置结果必须独立落到具体子 ASIN；
3. **关键词 × 子 ASIN × 当前产品目标**（业务判断层）— 完整判断的最小上下文，产品目标和库存承接由产品库存模块提供，本模块只引用。

## 2. 十项能力拆解：算子 / 判断点 / 人工确认

> 拆分标准：能用规则和公式跑出唯一结果的进「算子」；需要逐例语义判断、换个产品结论就不同的进「判断点」；必须运营确权的进「人工确认」。

| # | 能力 | 算子（确定性） | 判断点（需 LLM 逐例判断） | 人工确认 |
| --- | --- | --- | --- | --- |
| 一 | 共享市场关键词库构建 | 大小写/空格/标点/单复数/词形归一；别名↔标准词映射；跨来源去重且各留原值；首现与最近更新时间；词库四态机（有效/待确认/噪声/监控） | **J1** 这个词属不属于本品线（跨类目词、弱相关词的边界） | 运营确认或改判；临时加监控词 |
| 二 | 关键词分类与需求词组构建 | 一词多标签存储；词组汇总去重复计入；运营角色状态机 | **J2** 客户自动分类的误判纠正；**J2b** 运营角色定性（核心/探索/长尾/待验证）——**客户已给 174 词的 S必投/A重要/B补充 种子，判断的是如何扩展到 2000 词** | 错误分类与词组关系的修正 |
| 三 | 关键词市场事实与竞争结构计算 | 站点/时间/测量定义归一；需求·购买·供给·竞价分字段保留；需供比与头部集中度计算；来源三分层（官方/第三方估算/系统推导）；冲突不合并 | **J3** 竞争结构怎么解释（头部垄断 / 分散 / 竞争加剧） | — |
| 四 | 市场快照与变化识别 | 按频率存快照并带口径；可比性门禁（来源与统计条件一致才算变化）；增长下降计算；口径变更即置不可比 | **J4** 单期波动 / 连续趋势 / 样本不足；**J5** 变化集中在哪类需求（结构变了还是单词波动） | — |
| 五 | 关键词 × 子 ASIN 覆盖位置关系构建 | 产品↔父体↔子ASIN↔SKU↔广告对象映射；自然位与广告位分别落到 `词 × 子ASIN × 日期`；采集元数据（来源/时间/深度/站点）；覆盖四态；广告搜索词匹配补付费证据 | **J6** 无排名数据的四种原因判定（真实未覆盖 / 超采集深度 / 采集失败 / 未纳入监控）——有采集元数据时降级为算子 | 纳入监控的产品与词范围 |
| 六 | 覆盖与位置变化识别 | 同词同ASIN同位置类型跨日期比较；新增/丢失覆盖事件；上涨下降与连续性；按词组算覆盖结构变化 | **J6** 同上：真实覆盖变化 vs 数据缺失 | — |
| 七 | 产品目标匹配与库存约束绑定 | 读产品阶段/定位/主推辅助/当前目标（引用）；读库存承接能力（引用）；证据完整度降级规则；判断所用版本留痕 | **J7 需求与产品属性卖点的匹配度**（本模块最核心，无公式）；**J8** 该词在当前目标下承担什么业务作用（核心流量 / 细分探索 / 品牌防守） | 产品目标与主推辅助的确权 |
| 八 | 机会·缺口·风险·待验证证据评价 | 优先级中可计算部分（需求规模、变化幅度、缺口程度、变化连续性、是否主推） | **J9** 七类结论定性 + 主要依据 + 还缺什么证据；**J10** 影响程度与紧迫性排序 | 结论采纳与否 |
| 九 | 范围汇总与动态关键词日报生成 | 分指标正确汇总（量可加、排名不可加、比例加权、集中度重算）；一词多标签去重计入；完整范围 vs 本期可比范围分开 | **J11** 日报五问的答案本身 | — |
| 十 | 证据记录·追溯·下游交接 | 快照/事件/结论落库；三页引用关系；规则版本；向竞品页与广告页的结构化交付；接收竞品验证回写 | **J12** 与历史证据比较后的状态判定（新增/持续/加重/减轻/解除） | — |

### 判断点汇总（真 agent 的位置，12 个）

| 编号 | 判断点 | 所属能力 | 为什么不能用规则做 |
| --- | --- | --- | --- |
| J1 | 词是否属于本品线 | 一 | 客户文件已存在跨类目词与弱相关词，相关度字段只能粗筛，边界是语义问题 |
| J2 | 分类误判纠正 | 二 | 客户自动分类有误差，一词多标签的主次也要判 |
| ~~J2b~~ | ~~运营角色定性~~ **→ 降为输入** | 二 | 核心/探索/长尾/待验证是策略角色，与市场语义是两套体系。客户已给 174 个属性词的 S/A/B 种子（关键词1.html）。**2026-08-31 王楠拍定：`operator_role` 对 Agent 放开（Demo 例外），因此 J2b 不再是判断点 —— Agent 读得到答案就不能声称它在判。详见 `05-Agent输出面交底.md` 第 3.8 / 3.9 节** |
| J3 | 竞争结构解释 | 三 | 商品数、广告竞品数、需供比、头部集中度四个数字组合成一句话结论；且**两个来源的这几个数实测不一致**，解释时必须并列 |
| J4 | 波动 / 趋势 / 样本不足 | 四 | 阈值型规则会把季节性当趋势 |
| J5 | 变化落在哪类需求 | 四·九 | 需要把单词变化读成市场结构叙述 |
| J6 | 无数据的四种原因 | 五·六 | 采集元数据缺失时只能靠上下文推断 |
| **J7** | **词与产品的匹配度** | 七 | **本模块核心。方案明写“不因搜索量高就判高价值，也不对所有产品统一判某词好坏”** |
| J8 | 该词承担的业务作用 | 七 | 同一个词在防守目标和冲量目标下作用不同 |
| J9 | 七类证据结论定性 | 八 | 结论要带依据和缺口，不是打分 |
| J10 | 影响程度与紧迫性 | 八 | 优先级=先分析什么，不是阈值排序 |
| J11 | 日报五问答案 | 九 | 每天答案由当期数据决定 |
| J12 | 证据状态演化 | 十 | 新增/持续/加重/减轻/解除需比对历史语义 |

## 3. 六条横切一致性能力（跨三页，缺一条页面就自相矛盾）

| # | 约束 | 必须建的能力 |
| --- | --- | --- |
| 6.1 | 同一关键词在三页是同一个对象 | 单一共享词库 + 标准词/别名/分类/词组的唯一身份 |
| 6.2 | 市场事实与产品判断必须分开 | 两层结果物理分开存储，页面不得把市场事实渲染成产品结论 |
| 6.3 | 各类排名与份额不能混用 | **自然位 / 广告位 / ABA 排名 / 搜索词展示量份额 / 广告搜索结果首页份额 五个独立字段**，禁止任何换算 |
| 6.4 | 总览的变化必须能在详情复核 | 变化只在站点·词·来源·周期·测量定义全一致时才计算；每条变化带可下钻的快照引用；否则显示「暂不可比较」及原因 |
| 6.5 | 页面跳转不丢分析条件 | 站点·品线·时间范围·比较周期·关键词·子ASIN·产品目标 全程随跳转携带 |
| 6.6 | 数据不完整时必须明确停在哪里 | 九种状态可枚举：市场数据缺失 / 位置未采集 / 第三方估算 / 来源口径变化 / 数据过期 / 产品目标缺失 / 库存结果缺失 / 历史样本不足 / 竞品尚未验证 |

## 4. 五条红线（本模块明确不做）

1. 不生成加词、否词、出价、预算、暂停等广告动作（那是广告决策页）；
2. 不用展示量、点击、ACOS、展示量份额换算出未经采集的广告位置；
3. 不把市场头部 ASIN 自动当成已确认竞品；
4. 不因搜索量高就判定为产品机会；
5. 数据缺失时不补默认值、不生成超出证据范围的完整结论，AI 总结必须排在可核验数据之后。

## 6. 实现分层建议（做 Demo 时的先后）

| 层 | 内容 | 判断层依赖 | 建议 |
| --- | --- | --- | --- |
| L1 数据基建 | 词库身份、分类词组、市场事实、覆盖位置、采集元数据、九种状态 | 无 | **先做**，全部确定性，能力一/二/三/五的算子部分 |
| L2 算子 | 变化识别、汇总、优先级可计算部分、事件生成 | 无 | 紧接 L1，能力四/六/九的算子部分 |
| L3 判断层 | J1–J12，重点 J7 / J9 / J11 | 离线 Agent 产出，页面读结果 | 沿用产品库存模块的做法：Agent 只出判断，工作台自算下游算术 |
| L4 装配呈现 | 三页板块、下钻、跳转带参、状态标注 | 读 L1–L3 | 最后做 |

> 与产品库存模块的一致做法：判断层单独一个库、按 `run_date DESC, created_at DESC` 取每对象最新一次运行、中文成品文案在读取边界映射、枚举值绝不上屏。

## 7. 方案自己列的待确认项（影响能力口径，需用户拍）

1. 共享词库的纳入/移除/人工确认规则；
2. 日报默认比较周期；
3. **「关键词流量获取」的正式测量定义与可用来源**（缺定义则只能用代理指标）；
4. 自然位与广告位的采集来源、采集深度、更新频率；
5. 核心词/场景词/长尾词/待验证词的确认方式；
6. 产品目标、产品阶段、主推辅助的正式字段与规则；
7. 机会/风险/优先级的阈值或评价方式；
8. 库存承接结果向本模块的更新机制；
9. 关键词证据交给竞品页与广告页的结构化格式。
