## 0. 一句话结论

客户关键词文件的**字段维度已经很富**（2001 词 × 36 列，需求、购买、竞争、头部 ASIN 一应俱全），
缺的不是字段，而是**两条时间轴 + 一层关系**：

| 缺口 | 现状（已逐文件核对） | 后果 |
| --- | --- | --- |
| **市场事实的时间轴** | 全量关键词表 36 列里**一列时间都没有**，只有单快照 | 能力四整条（变化识别）跑不了 → 页面一的日报、词组变化、总览优先列表全部空转 |
| **`关键词 × 子ASIN` 的逐日位置** | **当期截面其实有**：2000 词里 **730 词（36.5%）的头部/前十字段含自有 ASIN**，涉及 **64 个自有子 ASIN**。缺的是①逐日时间轴 ②精确位次（源表只给「在前 3 / 在前 10」）③广告位（完全没有） | 能力五/六的**变化识别**跑不了，但**覆盖结构**有真实底子 → 构造成本比预估低一档 |
| **当前产品目标 + 主推/辅助** | v0.3.0 `dim_product_child` 有 `product_lifecycle`，但**没有产品目标、没有主推/辅助** | 能力七跑不了 → 只能出「事实」，出不了任何产品级结论 |

所以 Demo 数据构建的重心是：**把已有的当期截面拉成时间序列 + 补广告位 + 补一个产品目标层**。

## 3. 必须构造的九层数据

> 键、量级、必须造出的形态。全部带 `source` / `measure_definition` / `snapshot_date` / `comparable_flag` / `value_origin` 五个横切列。

### L1 `dim_market_keyword` — 共享市场词库
- 键：`keyword_id`；含标准写法、原始别名组、站点、品线
- 客户已有：2000 词 × 36 列（关键词3）+ 2000 词 × 35 列（关键词2，字段与数值均不同）
- 必须造：**词库四态**（有效 / 待确认 / 噪声 / 监控）、别名↔标准词分组、来源分层标记、首现与最近更新时间
- 量级：2000 词全量进 + 关键词2/关键词3 **双来源各存一行**（同 `keyword_id` 不同 `source`）；状态分布要肉眼可见（建议 有效≈1600 / 待确认≈250 / 噪声≈120 / 监控≈30），否则「词库质量」板块空转
- 冲突不合并：`商品数 / 需供比 / 广告竞品数 / 点击总占比 / 头部ASIN` 两来源实测不一致，必须并列展示差异

### L2 `dim_keyword_group` + `bridge_keyword_attribute` — 分类与需求词组
- 客户已有：`主要分类` + `所有分类标签`（关键词3，一词多标签已在源表）、`分类` + `匹配品牌`（关键词2）、`品牌分布` 81 个品牌、12+15 张分类 sheet、12 行分类汇总基线
- **运营角色客户已给种子**：关键词1.html 的 `S必投 / A重要 / B补充` + `★`，共 174 个属性词
- 必须造：比「分类」更细的**需求词组**聚类；把 174 个属性词的角色**扩展到 2000 词**并补确认状态；竞品品牌词 = `匹配品牌` 非空且 ≠ BAMBOO COOL（不必凭空造）
- 量级：需求词组 40–80 组；核心词 60 个、探索词 120 个、待验证词 60 个

### L3 `fact_keyword_market_snapshot` — 市场事实时间序列 ★最大缺口
- 键：`keyword_id × period_type × period_end`
- 客户已有：**一期**（无日期列）
- 必须造：多期。**周频 26 期**（2026-02-02 → 2026-08-03，ABA 口径）+ **月频 12 期**（2025-09 → 2026-08，月搜索量口径）。两种频率分行存，绝不混算
- 量级：2001 × (26 + 12) ≈ 76,000 行
- 必须造出的形态（每种至少一小组词，否则总览挑不出东西）：需求增长 / 需求下降 / 稳定 / 竞争加剧 / 头部 ASIN 替换 / 历史样本不足 / **口径变更导致不可比**

### L4 `fact_keyword_child_position_daily` — 覆盖与位置关系 ★第二大缺口
- 键：`keyword_id × child_asin × date × position_type(organic|ad)`
- **客户已有当期截面**：730 词 × 64 个自有子 ASIN 的「在前 3 / 在前 10」判定（关键词3 头部与前十字段）+ 关键词2 的 `相关ASIN` 字段作为第二来源
- 必须造：①把截面锚成**第 26 期（2026-08-03）**，往前 180 天的位次为构造值；②精确位次（源表只给档位）；③**广告位完全没有，全造**；④覆盖四态（仅自然 / 仅广告 / 双覆盖 / 未确认）；⑤采集元数据（来源 / 采集时间 / 采集深度 / 站点）
- 量级：监控词 300 × 重点子ASIN 30，按真实稀疏度 ≈ 1,050 对 × 180 天 ≈ **189,000 行**。若要覆盖 64 个交集子体全部，按实测覆盖数（B0B3LWGP36 一个就 363 词）需另算，建议先收窄
- 必须造出的形态：位置上涨 / 下降 / 新增覆盖 / 丢失覆盖 / 仅自然 / 仅广告 / 双覆盖，外加**四种「无排名」各自成组**：真实未覆盖 / 超采集深度 / 采集失败 / 未纳入监控（页面 §5.5 红线要求可区分）

### L5 `fact_keyword_child_ad_daily` — 付费侧词级证据
- 键：`keyword_id × child_asin × date`
- 客户已有：真数据（4 张搜索词/份额报表）
- 必须造：广告对象 → 子ASIN 桥表；把真实报表落到日粒度并补足未覆盖日
- 量级：约 600 对 × 180 天 ≈ 108,000 行
- 红线：`搜索词展示量份额` 与 `广告位` 是两个字段，禁止任何换算

### L6 `dim_child_product_goal` — 产品目标与主推关系（v0.3.0 缺）
- 键：`child_asin × effective_from`
- 必须造：当前产品目标（枚举 + 中文成品文案）、主推/辅助、生效时间、版本号
- 量级：342 子ASIN × 1–3 个历史版本 ≈ 600–900 行
- 说明：这是能力七的必需输入。缺了页面只能出覆盖事实，出不了机会/缺口/风险任何一条结论

### L7 `fact_keyword_market_change_event` + `fact_keyword_coverage_event` — 变化事件
- 必须造：市场变化事件 150–250 条；覆盖与位置变化事件 300–600 条
- 每条必须带**两期快照引用**（满足 §6.4 可下钻复核）

### L8 `fact_keyword_evidence` + `fact_keyword_audit_record` — 证据与盘点记录
- 七类证据：市场需求机会 / 产品覆盖缺口 / 核心位置风险 / 场景与长尾信号 / 库存受限机会 / 待竞品验证信号 / 数据不足
- 每条带：证据类型、影响对象、优先级、结论文案、主要依据、产品目标、库存限制、证据完整度、下一步验证页面、规则版本
- 量级：证据 300–450 条（30 个重点子ASIN × 5–15 条）；盘点记录 30 子ASIN × **3 次历史** = 90 条（少于 2 次，「与上次比」就没得比）

### L9 `fact_keyword_daily_report` — 动态关键词日报
- 必须造：**14 天**，每天五问五答 + 每条答案的下钻引用（少于 7 天连「今天 vs 昨天」都做不出来）

## 4. 构造硬约束（自洽门禁，先立后造）

| # | 门禁 | 为什么 |
| --- | --- | --- |
| G1 | 词级快照**最后一期（2026-08-03）= 客户原值逐字段相等**，且两个来源各自对账（关键词3 对关键词3、关键词2 对关键词2），往前才是构造 | 保证「真实数据」这句话站得住；来源不能串味 |
