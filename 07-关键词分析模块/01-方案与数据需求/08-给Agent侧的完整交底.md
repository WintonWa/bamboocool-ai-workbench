## 1. 这个模块是什么

关键词分析是 Bamboocool AI 运营工作台的一个业务模块，跑在统一外壳里（端口 18820），
和产品库存、广告分析、竞品分析并列。**最小判断对象是「关键词 × 子 ASIN」的关系对**。

它回答三个层次的问题：

1. 市场上的搜索需求在怎么变（词库层，与自有产品无关）
2. 自有产品在这些词上占到了什么位置（关系层）
3. 哪些词值得先看，为什么（判断层 ← **Agent 在这一层**）

模块身份：

| 项 | 值 |
| --- | --- |
| 模块 id / 路由前缀 | `keyword` → `/api/keyword/<资源>` |
| 参数前缀 | `kw.` |
| CSS 作用域 | `[data-module="keyword"]` |
| 数据包 | `07-关键词分析模块/02-数据构建/v0.1.0/keyword_demo.sqlite`（24 表 / 423,555 行 / 107.5 MB） |
| 表名前缀 | `dim_keyword*` / `fact_keyword_*` / `bridge_keyword_*` |
| 模块代码 | `09-工作台/modules/keyword/{module,data,compute,rules}.py` + `web/modules/keyword.{js,css}` |

## 2. 三个页面的结构

页面 id 就是 URL 段名，物理深链可直接访问。

### 页面一 `kw-overview` 关键词动态与机会总览　`/keyword`

一天一屏，回答「今天有什么变化、先看什么」。

| 板块 | 回答什么 | 读哪里 | Agent 参与 |
| --- | --- | --- | --- |
| 动态日报（hero + 五问五答） | 今天流量怎么样、谁在涨跌、核心词覆盖有没有变、有什么新信号、先看什么 | `fact_keyword_daily_report` | **B 全部五答** |
| 数据范围与状态 | 这一屏覆盖了多少词多少子体、哪些范围本期不参与比较 | `dim_keyword_scope` + 各表计数 | 否 |
| 市场需求与词组变化 | 哪类需求在动、变化集中还是分散 | `fact_keyword_market_change_event` + 词组桥表 | **C 事件类型/连续性/label** |
| 自有核心词覆盖与位置变化 | 自有产品在核心词上新增/丢了什么位置 | `fact_keyword_coverage_event` | **D 同上** |
| 机会缺口与风险优先列表 | 先分析什么，依据是什么 | `fact_keyword_evidence` | **A 全部** |

### 页面二 `kw-market` 市场关键词库与单词深研　`/keyword/kw-market[/<keyword_id>]`

**列表态**（三板块）：共享词库范围与质量 → 需求词组与市场结构 → 市场关键词比较区（可排序表）

**详情态**（五板块，点词进入）：

| 板块 | 回答什么 | 读哪里 |
| --- | --- | --- |
| 词身份与别名 | 这个词是什么、归哪类、什么角色 | `dim_keyword_term` + `dim_keyword_alias` |
| 双频率市场事实深研 | 周线和月线各自怎么走（**两频率绝不折算成同一周期**） | `fact_keyword_market_snapshot` |
| 两份来源的同期数值 | 两个来源对同一指标给出不同数值时并列保留 | 同上，`source_code` 区分 |
| 头部 ASIN 与竞品线索 | 谁在这个词的头部，自有 ASIN 在不在 | `fact_keyword_head_asin` |
| 关键词与产品关系 | 哪些子体已建立关系，点行进盘点页 | `dim_keyword_child_pair` |

### 页面三 `kw-child` 子 ASIN 关键词盘点　`/keyword/kw-child[/<child_asin>]`

单个子体一屏，六板块。

| 板块 | 回答什么 | 读哪里 | Agent 参与 |
| --- | --- | --- | --- |
| 决策摘要（hero） | 这个子体有多少待处理事项，最要紧的一条是什么 | `fact_keyword_evidence` | **A** |
| 产品上下文 | 这是什么产品、当前目标、库存能不能承接 | ATTACH 产品包 + `dim_keyword_child_goal` + `fact_keyword_child_absorb` | 否（上游带入） |
| 关键词覆盖结构 | 覆盖长什么样（堆叠比例条）、哪些词组有缺口 | `dim_keyword_child_pair` + 词组桥表 | 否 |
| 自然位与广告位变化 | 182 天位次怎么走、事件构成、哪些词在连续走弱 | `fact_keyword_child_position_daily` + `fact_keyword_coverage_event` | **D** |
| 缺口机会与风险 | 七类证据分组，同类只展开 3 条 | `fact_keyword_evidence` | **A** |
| 盘点记录 | 同一子体历次盘点的变化 | `fact_keyword_audit_record` | **E** |

## 3. 框架功能（外壳提供什么）

模块只交模块文件，外壳零改动。Agent 侧需要知道的是**页面有哪些能力**，因为这决定了
Agent 不必自己做什么。

**外壳提供**：顶栏与页签、对象栏（脊椎 342 个子 ASIN）、参数面板、筛选 chip、
详情抽屉、浮层、URL 即状态（物理深链 + 后退恢复）、故障隔离（一个模块坏了其余照常）。

**页面自己会算的**（Agent 不要输出，会被覆盖）：

- 覆盖结构统计（五态分区、组内覆盖率、缺口）
- 位置聚合（当日平均自然位、最好/最差、连降天数）
- 词组汇总（按 `dedup_weight` 分权）
- 优先级重排（按四个权重参数）
- 日报每问上方的结构化数字

**十个参数**，全部会真改数字（不是回显）：

| 参数 | 类型 | 默认 | 范围 | 影响 |
| --- | --- | --- | --- | --- |
| `kw.compare` | enum | `day` | day/week/4week | 日报环比基期 |
| `kw.weak_rank` | num | 20 | 3–100 | 自然位「偏弱」的门槛 |
| `kw.collect_depth` | num | 144 | 48–288 步 48 | 采集深度，改了会把「有排名」重分类成「超出采集深度」 |
| `kw.streak_days` | num | 7 | 3–30 | 连续走弱的判定天数 |
| `kw.rank_shift` | num | 3 | 1–30 | 位次变化算「显著」的名次门槛 |
| `kw.group_dedup` | bool | 开 | — | 一词多组是否按权分摊 |
| `kw.w_demand` | num | 0.30 | 0–1 步 .05 | 优先级权重 · 需求规模 |
| `kw.w_change` | num | 0.30 | 0–1 步 .05 | 优先级权重 · 变化紧迫 |
| `kw.w_push` | num | 0.20 | 0–1 步 .05 | 优先级权重 · 主推加权 |
| `kw.w_evidence` | num | 0.20 | 0–1 步 .05 | 优先级权重 · 证据完整度 |

参数以 query 传，由外壳夹紧后交给模块。**这意味着 Agent 给的 `priority` 会被页面按权重重排**——
Agent 出的是原始意见，不是最终顺序。

## 5. 数据是怎么来的

不是导出的现成库，是从客户三个源文件构造的九层结构。

**客户真给了什么**（`数据源/AI广告对接数据-总20260803/10.关键词/`）：

| 文件 | 内容 | 关键发现 |
| --- | --- | --- |
| 关键词3.xlsx | 2001 行 × 36 列，唯一 1991 词 | 需求/购买/供给/竞价/头部 ASIN 全有，但**无时间列**，只是单快照 |
| 关键词1.html | 162 属性词 × 12 维度矩阵 | 不是工具报告，是**运营人工标注**的构词矩阵，`优先级` 列就是已定的角色种子 |
| 关键词2.xlsx | 独有流量占比、流量词类型、匹配品牌、80 品牌分布 | 与关键词3 **对同一个词的数值真实冲突** |

三条勘查阶段推翻的旧判断，直接影响 Agent 该怎么判：

1. **位置层不是「客户完全没给」**。2000 词里 730 词（36.5%）的头部/前十字段含自有 ASIN，
   涉 64 个自有子 ASIN。缺的只是逐日时间轴、精确位次（源表只给「在前 3 / 在前 10」）和广告位。
   → 末期截面是**真值**，往前是构造值，靠 `value_origin` 区分。
2. **关键词1 是运营已标好的角色种子**（S 必投 21 / A 重要 55 / B 补充 86，★ 59）。
   → J2b 要判的是「如何扩展到 1991 词」，不是凭空定义角色。
3. **两来源对同一词的数值真实冲突**（`mens underwear` 广告竞品数 548 vs 495、
   点击总占比 0.2119 vs 0.3250、第二头部 ASIN 不同）。
   → J3 竞争结构解释**必须并列两个来源，不能合并**。

**九层结构**（24 表全清单见 `06-数据字典.md`）：

```
L0 口径锚          dim_keyword_scope
L1 共享词库        dim_keyword_term(1991) / alias(118) / brand(80) / attribute(5277)
L2 需求词组        group(59) / bridge_keyword_group(2318, 带 dedup_weight) /
                   attribute_seed(162) / attribute_combo(324) / category_rollup(11)
L3 市场事实        market_snapshot(77,400 · 周26+月12) / head_asin(42,378)
L4 覆盖与位置      child_pair(901) / child_position_daily(163,982) / state_label(21)
L5 流量            child_traffic_daily(121,031) / traffic_attribution_daily(4,938)
L6 产品上下文      child_goal(434) / child_absorb(342)          ← 上游带入
L7 变化事件        market_change_event(148) / coverage_event(973)  ← Agent C/D
L8 证据与盘点      evidence(562) / audit_record(90)                ← Agent A/E
L9 日报            daily_report(14)                               ← Agent B
```

构建器在 `02-数据构建/`：`lib_kwsrc.py`（源读取+选样）、`build_keyword_dataset_v010.py`、
`lib_l3.py`…`lib_l89.py`。46 条构建门禁 + `verify_v010.py` 13 条落盘复核（客户原值写死断言）。

**选样是有配额的**，300 个监控词分十桶全满：核心大词 40 / 零覆盖缺口 40 / 自有品牌 25 /
竞品品牌 30 / 属性 45 / 场景节日 30 / 尺码颜色数量 20 / 长尾高转化 35 / 噪声 20 / 拼写变体 15。
30 个子体覆盖 5 个父体。这个配额保证每类判断都有对象，Agent 不会遇到「某类证据一条都造不出来」。

## 6. 两个演示对象必须一起用

Agent 自测时如果只打一个对象，很多档位会恒为 0 却看不出问题。

| | `B0B3LWGP36` | `B0CBPXNC1M` |
| --- | --- | --- |
| 数据性质 | 推导（66 对全是真实锚点） | 模拟（0 个真实锚点） |
| 关系对 | 66 | 28 |
| 五态实际出现 | 只 2 态 | **4 态**（含超采集深度 252 点） |
| 仅广告 / 未覆盖 / 偏弱 | 0 / 0 / 0 | 3 / 3 / 17 |
| 演什么 | 覆盖看着齐全，但按词组分组后 14 组仍有缺口 | 五态可区分，「产品没覆盖」与「系统没采到」是两回事 |

方案 §5.5 把「未覆盖」与「未采集到」混为一谈列为红线。**只有 `B0CBPXNC1M` 演得出这个区别。**

上屏文案四条纪律：

1. **枚举码零命中**。`full` / `partial` / `coverage_gap` / `organic_down` 这类码值一个都不能出现在

3. **性质与状态只用词表内的词**。性质：真实/推导/模拟/混合；
   状态：正常/加载中/空结果/过期/缺失/待确认/失败。
4. **两个数相等不分两句**。
