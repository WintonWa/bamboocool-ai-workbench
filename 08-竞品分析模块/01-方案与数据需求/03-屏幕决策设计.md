# 竞品分析模块｜屏幕决策设计

版本 v0.1（2026-08-30）· 模块 id `competitor` · 判断对象：**竞品产品族（父 ASIN）**

本文是全局信息设计原则 §11 要求的设计门槛文件。缺它，前端只能算探索原型。

---

## 1. 页面用户、判断对象、核心问题

| 项 | 值 |
| --- | --- |
| 用户 | 亚马逊运营（组长与执行运营），每天要决定先处理哪个竞争压力 |
| 最小判断对象 | **竞品产品族（父 ASIN）**。子 ASIN、报价、关键词是底层观察对象，只在详情展开 |
| 总览核心问题 | 当前哪些竞品威胁最大或变化最明显，先看谁 |
| 详情核心问题 | 变化发生在什么时间、涉及哪些信号、哪些是事实哪些只是同期 |
| AI 负责 | 变化结论与依据、同期关系是否成立、关注分级、影响范围、报告选题 |
| AI 不负责 | 观察数据本身、广告动作预算出价、综合威胁分数 |

## 2. 信息传达目的

1. 让运营在不读 AI 长文本的情况下，就能从比较表里看出谁最值得处理；
2. 让"价格/促销、销量/排名、流量/关键词"三类变化在同一根时间轴上可核对；
3. 让事实、推导、假设、不能确认的因果四者在页面上不混为一谈；
4. 让一条竞品证据能带着对象、时间、来源、可信状态和深链交给关键词页与广告页。

## 3. 首屏阅读顺序

总览：

> 范围与数据状态（外壳槽位）→ 竞品洞察带 → 威胁比较表 → 进入单竞品

详情：

> 顶部判断带 → 共同时间线 → 产品族与报价 → 关键词入口证据 → 事实与假设分离 → 交给下游

## 4. 总览与详情分工

总览只定位：看谁、程度、发生时间、与上期相比、去哪里继续看。**不承担因果解释，不给每个竞品一张长卡片。**

详情只解释：哪几组数据共同形成结果、事件何时发生、哪些是事实推导假设、依据在哪。**不重复堆总览的汇总数字。**

## 5. 组件与它表达的数据关系

### 总览

| 组件 | 表达的关系 | 为什么是这个组件 |
| --- | --- | --- |
| 竞品洞察带（紧凑一条带） | 当前范围最重要的威胁是什么、涉及谁、压力在哪一维、证据入口 | 法则五：AI 结论在数据关系之后，且不与比较表重复同一句话 |
| 变化计数带（活动价格 / 市场表现 / 关键词位置 / 流量结构 四个可点数字） | 各类变化各涉及几个产品族 | 全局 §4.4：摘要数字必须能点击过滤主视图，不做四张等权 KPI 卡 |
| **威胁比较表**（主工作区，唯一最强焦点） | 多个产品族谁更严重、变化在哪、何时发生、证据是否完整 | 法则四：多对象比较用排序表格；V5 §7 明确要求把父 ASIN 大卡片改成可纵向比较的表格 |

威胁比较表列（V5 §3.2）：

| 列 | 内容 |
| --- | --- |
| 竞品身份 | 品牌 · 父 ASIN · 子类目 |
| 当前威胁 / 变化 | 关注分级 + 最重要那条变化的短标签 |
| 市场结果 | 小类排名与销量量级变化方向及幅度 |
| 价格与促销 | 当前件单价、价格带、近期事件 |
| 流量与关键词 | 主要入口词与位置变化 |
| 发生时间 | 最近关键变化起始日与持续天数 |
| 证据完整性 | 数据性质 + 状态（正常/过期/缺失/待确认） |
| 操作 | 查看共同时间线 |

排序：关注分级 → 变化幅度 → 运营手工关注。**不生成综合威胁分数**（方案 §5.4、V5 §3.2、禁止清单第 10 条）。

### 详情

| 组件 | 表达的关系 |
| --- | --- |
| 顶部判断带 | 身份、当前变化、发生时间、压力维度、证据完整性，并写明"同期不等于因果" |
| **共同时间线（唯一最强焦点）** | 四轨共用横轴：市场结果轨 / 价格促销轨 / 流量与位置轨 / 证据事件轨 |
| 产品族与报价关系 | 变化落在整族、某子体还是某报价；件单价口径 |
| 关键词入口证据 | 与该竞品变化最相关的入口词、位置与共享变化、时间与来源 |
| 事实与假设 | 三段分列：可观察事实 / 分析假设 / 不能确认的因果 |
| 分析记录与交接 | 与上一版比较（新增/持续/加重/减弱/解除）、下游证据对象 |

共同时间线并列的序列、粒度与区间（验收 A5）：

| 轨 | 序列 | 粒度 | 区间 |
| --- | --- | --- | --- |
| 市场结果 | 小类排名、滚动 30 天销量量级、评分与评论数 | 日 | 2026-02-05 ~ 2026-08-03 |
| 价格促销 | 成交价、划线价、Coupon、Deal 段 | 日 | 同上 |
| 流量与位置 | 关键词自然位与点击/转化共享（周）、流量结构（月） | 周 / 月 | 同上 |
| 证据事件 | 观察中断、来源冲突、更新过期 | 区间 | 同上 |

粒度不同的轨必须在轨名旁写明粒度，不假装完全同步（V5 §4.2、契约 §6.5）。

## 6. 筛选、选中、下钻、返回

筛选项由模块声明、外壳渲染（契约 §7、§8.2 `export const filters`）：竞品或 ASIN 搜索、时间范围、子类目、变化类型、证据状态。筛选同步更新洞察带、计数带、比较表和 AI 上下文。

下钻：点比较表的"查看共同时间线"进入内嵌详情路由（契约 §8.8 URL 即状态），不用窄抽屉承载时间线。整行不默认可点（全局 §9）。

返回：外壳恢复筛选、排序、选中对象、时间范围与滚动位置。

## 7. AI 上下文与依据定位

AI 绑定当前筛选与选中的产品族，按全站固定七段结构回答（当前对象和范围 / 一句话结论 / 关键数据关系 / 时间与影响范围 / 不确定性 / 建议继续核对什么 / 可定位依据）。

每条结论都指回具体轨道与日期。AI 不使用"导致"描述只有相关性的现象，不输出广告动作。同一页面只有外壳提供的一个 AI 入口，模块不自建对话 UI。

## 8. 状态

上屏只用契约 §6.6 的两套固定词表，不自造说法：

- 数据性质：真实 / 推导 / 模拟 / 混合
- 数据状态：正常 / 加载中 / 空结果 / 过期 / 缺失 / 待确认 / 失败

模块必须覆盖的具体状态：

| 状态 | 页面行为 |
| --- | --- |
| 该族未纳入分析 | 三个事实看板照常显示，结论区写尚未分析并给分析入口 |
| 证据不足 | 不给关注分级、不进比较表排序前段、不计入变化计数；写明缺什么、因此哪些结论不生成、去哪里补 |
| 未纳入抓取（只有快照） | 只给当期事实，不给任何变化结论 |
| 当期未落入重点词前三 | 关键词看板说明暂无位置观察，不猜排名 |
| 观察中断 / 来源冲突 / 更新过期 | 落在证据事件轨上，缺口两端不相减 |

## 9. 当前不做

竞品库存探测；竞品出价预算花费估算；广告动作；全类目选品；季节性进入默认关注规则；综合威胁分数；把异常转成待办。

## 10. 可验证的验收标准

| # | 标准 |
| --- | --- |
| V1 | 5 秒内识别当前范围、数据截止时间与判断对象 |
| V2 | 10 秒内从比较表找到最值得处理的产品族 |
| V3 | 15 秒内说出变化何时发生、涉及哪些信号、程度多大 |
| V4 | 不读 AI 也能从比较表和时间线独立得出主要结论 |
| V5 | 共同时间线能同时核对市场结果、价格促销与流量位置，且悬停同日四轨同步高亮 |
| V6 | 页面明确区分事实、假设与因果未知 |
| V7 | 一条证据能带对象、时间、来源、可信状态和深链进入关键词页或广告页并可返回 |
| V8 | 页面无综合威胁分数、无等权 KPI 卡墙、无字段级卡片 |

## 12. 未确认的阈值、算法、口径与因果（验收 A7）

以下全部来自决策记录 §9「待客户或数据确认」，**不自行补齐**，页面上以"待确认"状态呈现：

1. 威胁优先级的计算方式（当前用可解释分级 + 依据条目 + 手工关注，不给分数）；
2. 洞察带的刷新频率与固定结构细节；
3. 筛选项、变化类型、子类目的具体口径；
4. 价格、销量、排名、流量、关键词变化、流量结构的可用字段；
5. 各指标的时间粒度、历史范围与更新时间；
6. 第三方插件或接口的实际可接入能力；
7. 来源标识、证据记录与下游交接格式；
8. 哪些关系可由数据验证、哪些只能作为待验证假设。

同期与因果分开表述：所有多信号同时出现的情形只表达为"同期变化"或"可能相关"，页面用独立字段记录"还缺什么证据才能升级"，不出现"因为降价所以排名上升"这类写法。
