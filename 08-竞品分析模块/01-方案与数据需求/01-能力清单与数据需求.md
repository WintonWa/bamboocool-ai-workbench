## 3. 判断点清单（这些是本模块真正的 Agent 部分）

其余全部是算子和装配。判断点共六处：

| 判断点 | 要判断什么 | 为什么不能用公式 |
| --- | --- | --- |
| J1 竞争关系是否成立 | 一个竞品族是否真的与某个自有子体竞争，凭哪一类依据 | 同类目同价格带不等于竞争；材质、定位、包装数、人群都可能让两者不抢同一个买家 |
| J2 变化是否代表产品族 | 一个子体或一个报价上的变化，能否上卷成整族事件 | 覆盖比例只是参考；71 个变体里 3 个降价与 3 个主销变体降价含义完全不同 |
| J3 变化性质分类 | 是短期跳变、持续变化，还是数据中断造成的假变化 | 断更 14 天后回来的“BSR 大涨”是观察缺口不是市场变化 |
| J4 同期关系是否成立 | 多类变化同期出现时，是同期证据、先后关系、独立变化还是证据不足 | 相关性判断需要看每条轨的起止、幅度、覆盖与数据可信度组合 |
| J5 关注程度与影响范围 | 该不该优先看、凭什么、可能影响哪些自有产品与关键词 | 方案明确禁止伪精确综合分数，要求分级 + 可解释依据 + 允许运营手工调整 |
| J6 报告选题与表达 | 本周期挑哪几条、怎么把对象/时间/证据/未确认事项讲清 | 报告是“最值得关注”，不是“阈值命中项全列” |

## 5. 六条横切约束（方案 5.1–5.6）→ 字段级要求

| 统一规则 | 落到数据与界面的硬要求 |
| --- | --- |
| 统一业务对象 | 每条结果必须带 `object_level`（family / child / offer / keyword），总览任一结论可回到详情的具体对象 |
| 统一时间范围 | 每条观察带 `observed_at` + `coverage_period` + `grain`（日/周/月）；月度估算不得渲染成每日事实；页面跳转保留同一观察窗 |
| 统一证据表达 | 每条结果带 `data_nature`：observed / third_party_estimate / derived / hypothesis / missing，并保留 `source`、`data_time`、`analysis_time` |
| 统一关注程度 | 关注等级必须附依据条目；保留 `manual_flag`；不出现无法解释的精确威胁分数 |
| 统一因果边界 | 同期出现只能表达为“同期变化 / 可能相关”，升级为因果需要额外证据字段支撑 |
| 统一页面上下文 | 跳转携带来源页、自有产品、关键词、竞品、时间范围、变化类型；返回恢复原范围与位置 |

界面文案纪律（沿用本项目已定规则）：数字与数字的名字直接显示；口径解释收进 ⓘ；防御性自述不写进页面；`data_nature` 这类枚举值不得原样上屏，必须映射成中文成品文案。

## 6. 方案明确的边界（不做）

- 竞品库存探测（依赖大量买家账号，准确性不足）；
- 竞品广告出价、预算、花费的估算结论（无可靠来源时不生成）；
- 广告预算/出价/投放动作（属广告模块）；
- 完整选品、全类目竞品研究、第三方工具全功能；
- 季节性等未被业务确认的因素进入默认关注规则。

# 第二部分：可把玩需要哪些数据

## 7. 本页“可把玩”的判据

不是页面有数字，而是下面每一条都能跑：

1. 总览四类变化版图各自都有对象，切换有结果，同一竞品能同时出现在多类；
2. 关注顺序可解释：点开任一竞品能看到它排在这里的依据条目；
3. 从总览任一结论可下钻到详情的具体对象 + 具体时间段，返回不丢范围；
4. 详情价格活动看板能看出“活动开始 → 活动结束 → 价格恢复”的完整过程与价格差变化；
5. 共同时间线三轨对齐，能看出同期与非同期两种情况，且能演示“同期但不能判因果”；
6. 至少一个竞品的变化只发生在某个子体或某个报价，页面不把它上卷成整族结论；
7. 至少一个竞品证据不足（断更/过期/来源冲突），页面明确给出不下结论；
8. 分析记录能与同一竞品的上一版本比较，看到关注状态的变化；
9. 至少一条竞品证据能带着上下文进入关键词页与广告页，并保留返回入口；
10. 关注规则参数可调，调完排序与版图跟着变（这是“可把玩”与“可看”的分界）。

## 8. 反向依赖闭包

四条链，每条都必须走通到最上游输入：

```text
价格活动链：日观察价格/划线价/Coupon/Deal → 成交价还原 → 与基线比较 → 价格活动事件 → 与自有价差变化 → 时间线价格轨 → 关注依据
市场表现链：BSR/销量量级/评分/评论 观察序列 → 周期比较 → 市场变化 → 时间线市场轨 → 关注依据
关键词流量链：关键词×对象×日期 位置与共享 → 覆盖增减与位置变化 → 与自有同词位置关系 → 时间线关键词轨 → 关注依据 + 关键词页交接
证据与结论链：三轨事件 → 对齐与前后开窗 → 同期关系 → 证据完整度 → 关注程度与影响范围 → 动态报告 + 分析记录 → 广告页交接
```

| 徽章 | Best Seller 200/500、Amazon's Choice 355/500、New Release 116/500、AC 关键词 355/500 |
| 索引误报 | 索引里“月销量/月销售额是时间字段且格式混杂”是扫描器误判，实测是整数件数与金额，不要按日期去修 |

### 10.2 关键词表：`关键词2.xlsx` / `关键词3.xlsx`

真实可用的竞品关键词位置信号：每个关键词带 `#1/#2/#3 前三ASIN` + 各自 `点击共享`、`转化共享`，另有 `相关ASIN`（自有相关产品列表）、月搜索量、ABA 排名、商品数、需供比、广告竞品数、PPC 竞价、词分类标签；`关键词3` 另有 `竞品品牌词` 分表。2000 词量级，**同样是单期月度快照**。

这一份让“竞品在某个词上占前三、占多少点击共享”成为可派生的真实事实，但只覆盖前三名、只有一个时点。

### 10.3 自有侧与竞品侧的接缝（关键）

| 集合 | 规模 | 关系 |
| --- | --- | --- |
| 自有（库存 v0.3.0） | 342 子体 / 5 父体，全部为男士长平角（Men's Boxer Briefs） | 与竞品表**同一小类目** |
| 自有（广告 v0.2.0） | 521 子体 / 5 父体 | 与库存集交集 188 子体，共享 2 个父体 `B0D9FLMR6N`、`B0GQXK2Q58` |
| 竞品表 1607 个 ASIN | — | 与自有两套集合**交集为 0**，品牌里也没有 BAMBOO COOL |
| 关键词表里的自有 ASIN | B088W\*、B0BZV\* 系列 | 在广告集内，**不在库存集内** |

结论：类目对得上（都是男士内裤），但没有任何一行能自动把“竞品 ↔ 自有”连起来。竞争关系表 T4 必须显式构造，这不是可选项。

## 11. 必须构造的部分与构造锚

| 缺口 | 构造方法 | 真实锚 | 不变量 |
| --- | --- | --- | --- |
| 逐日价格与活动（T7） | 以快照价格为终点反向生成 180 天路径，按场景注入活动段与阶梯降价 | 快照 `价格($)`、`FBA($)`、包装尺寸分段、类目价格中位 20.00 | 末日价格必须等于快照价格；活动价 ≤ 日常价；活动结束后回到区间内 |
| 逐日市场表现（T8） | 由快照 BSR/月销量/评分数/月新增评分/留评率反推月度速率再摊到日 | 快照四项 + 留评率 0.014 量级 | 窗口累计必须加回快照月销量；评分数单调不减；月新增评分与留评率自洽 |
| 关键词位置（T9） | 前三名与共享用真实值锚定当期，其余排名按场景生成路径 | `#1–#3 前三ASIN` + 点击/转化共享 + ABA 排名 | 当期前三必须与源表一致；同一词同一天排名唯一 |
| 流量结构（T10） | 全部构造，明确标注第三方估算 | 无 | 三项占比合计为 1；不得由占比反推竞品花费/出价/预算（方案红线） |
| 竞争关系（T4） | 按小类目 + 价格带 + 材质/包装数/人群四类依据逐条建立，带确认状态 | 自有 342 子体属性 + 竞品类目路径与价格 | 每条关系必须有依据类型与确认状态；允许“待核对” |
| 报价与卖家（T3） | BuyBox 卖家用真实值，其余按 `卖家数` 补足 | `卖家数`（多为 5）、`BuyBox卖家`、`卖家所属地`、`配送方式` | 报价数 ≤ 卖家数；同一时刻只有一个 BuyBox |
| 数据状态（T12） | 专门构造断更、过期、来源冲突三种状态 | 无 | 断更区间内不得同时存在正常观察 |

## 12. 需要用户拍板的项（blocked）
