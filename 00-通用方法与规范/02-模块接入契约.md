## 1. 这份契约要解决什么问题

产品与库存、广告两个模块是各自独立建的，各占一个端口、一套 `index.html`、一套 `app.css`。把它们合并时发现四类冲突，全部来自同一个假设——每个模块都以为自己独占整个 origin、整个 JS 全局作用域、整个 Python 模块名空间、整个样式表：

| 层 | 实测冲突 |
| --- | --- |
| HTTP 路径 | `/`、`/app.css`、`/app.js`、`/api/meta` 四条完全撞车。`/api/meta` 同一路径、两套载荷契约无一个共同键 |
| Python 模块名 | 两边都叫 `data` / `compute` / `rules`，一个进程只能绑一次 |
| JS 全局标识符 | 7 个对撞：`$` `el` `S` `pc` `load` `renderList` `renderScope`，两边都裸在全局 |
| CSS | 一边用 `#id` 加裸元素选择器（`section{}`、`table{}` 无作用域），另一边全用 class；10 个类名双定义，`.grid` 在一边是布局原语、在另一边是数据表格类名 |

设计系统反而几乎不冲突：两套 `:root` 的 19 个变量里 16 个字节级完全相同。也就是说重复的不是审美判断，是三份各写一遍的同一套值。

**结论：合并的成本不在业务逻辑，在命名空间。而这个成本随模块数线性增长。** 本文的规则都很轻，但必须在动笔前生效——建完再改要动四倍的地方。

### 1.1 运行时选定：零依赖 Python，不迁 V5 的技术栈（V6 决定）

`/Users/linsen/BAM/V5-项目方案与成品/01-V5前端成品/` 里有一个已实现统一外壳的前端成品，它的**信息架构值得借鉴**（见 6.6 与 8.8），但**运行时不迁移**。依据是实测数字，不是偏好：

| 项 | V5 成品 | 当前重建栈 |
| --- | --- | --- |
| 依赖 | `node_modules` 944 MB | 零第三方依赖（`/usr/bin/python3` stdlib + `sqlite3`） |
| 构建 | 必需（`vinext build`） | 无，静态文件每次请求重读 |
| 关键组件成熟度 | `vinext` **0.0.55**、`@vitejs/plugin-rsc` **0.5.26**，跑 dev/build/start 全靠它 | stdlib |
| 目标运行时 | Cloudflare Worker（wrangler 4.92 / miniflare / `worker/index.ts`） | 本机进程，只绑 `127.0.0.1` |
| 数据层 | **没有**。`app/workbench/` 与 `demo-data.ts` 内 `fetch` / `/api/` / `sqlite` 命中数为 0，8 个页面全读硬编码 mock（54 KB） | 只读 SQLite，489 MB 产品包 + 20.8 MB 广告包 |

两条决定性的：一是 0.0.x 的 `vinext` 是整条 dev/build/start 链的单点，本机内存常在 3 GB 上下、再叠 944 MB 依赖和一次 RSC 构建不划算；二是 V5 **没有数据层**，所以它省不掉本项目最贵的那部分工作——库存的判断链（`compute.py` 约 50 KB）、预测读取、ECharts 逐日图（`daychart.js` 481 行）、广告的四表现场聚合，这些在 V5 里一行都不存在。迁过去等于要么用 TS 重写这些（数字可能被悄悄改掉），要么把 Python 留在后面当 API 服务、前面再挂一个 Worker——两个运行时比一个脆。

所以 V6 = **V5 的信息架构 + 当前的零依赖运行时**。视觉不采用 V5 的 Organic Soft-Tech，沿用工作台已定型的浅色 token 体系。

## 3. 你要交什么、不要交什么

| 要交 | 不要交 |
| --- | --- |
| `modules/<模块名>/module.py` 一个自描述文件（见第 8 节） | 对外壳任何文件的改动 |
| `modules/<模块名>/{data,compute,rules}.py` 三个业务文件 | `server.py` / `start.py` / 自己挑的端口 |
| `web/modules/<模块名>.js`（ES module） | `index.html` / `app.css` / 自己的 token 定义 |
| `web/modules/<模块名>.css`（带作用域） | 自己的浮层、抽屉、导航、筛选栏实现 |
| 自己的数据构建脚本与独立 SQLite | 对产品包的任何写操作 |
| 一份"屏幕决策设计"（见第 10 节） | 自己的 AI 对话 UI |

外壳、路由、导航、筛选上下文、AI 交互窗口、`tokens.css` 由工作台统一提供并统一维护。

**接入一个模块 = 新增两个目录里的文件，外壳零改动。** 撤掉一个模块 = 删掉这些文件加它的数据包，不留残引用。这条是硬要求，见第 8 节。

## 5. 三条命名空间硬规则

**5.1 路由前缀。** 所有接口走 `/api/<模块名>/<资源>`，例：`/api/keyword/terms`、`/api/keyword/term/<id>`、`/api/competitor/rivals`。禁止占用 `/api/meta`（那是壳级的数据截止时间与模块清单），模块自己的元信息放 `/api/<模块名>/meta`。

**5.2 参数前缀。** 可调参数键一律带模块前缀，例 `kw.opportunity_min_volume`、`cmp.threat_score_min`。一条 query string 会同时携带全部模块的参数，各模块只解析自己前缀下的键并忽略其余。参数必须**夹紧**在声明的 `(下限, 上限, 步长)` 内。

**5.3 CSS 作用域。** 模块样式全部写在 `[data-module="keyword"] { … }` 之下。

- 零 `#id` 选择器；
- 零裸元素选择器（不写 `section{}`、`table{}`、`h2{}`）；
- 只使用 `tokens.css` 已有的变量，不新增自己的色值、圆角、阴影；确需新变量先提出来加进 `tokens.css`，不要就地定义。

## 6. 数据层规则

**6.1 独立 SQLite，只读打开。** 用 `file:…?mode=ro` URI 打开，路径集中在 `core/paths.py` 并支持环境变量覆盖，不要在业务文件里写死绝对路径。

**6.1b 取连接一律用 `core.db.pool(路径)`，绝对不要自己 `@lru_cache` 缓存 `db.connect()` 的返回值。**

服务是 `ThreadingHTTPServer`，前端一个页面会并行发好几个请求（侧栏取 meta、正文取对象详情，走 `Promise.all`）。一个 SQLite 连接被两个线程同时 `execute` 会**偶发** `sqlite3.DatabaseError: database disk image is malformed` —— 文件其实没坏（`quick_check` 是 ok 的），是连接不能并发用；`check_same_thread=False` 只解除检查，不做串行化。

`db.pool()` 按线程各给一个连接。这个坑范例模块第一版踩过：用 `@lru_cache` 缓存单连接，页面一并行请求就 500，而且是偶发——最难查的那种。回归探针 `tests/probe_concurrency.py` 守着它，压 210 个并发请求必须全 200。

**6.2 表名带模块前缀。** `fact_keyword_*` / `dim_keyword*` / `bridge_keyword_child` / `plan_keyword_*`，竞品同理用 `competitor`。跨库 `ATTACH` 时靠前缀避免歧义。

**6.3 不要在自己的包里重建 `dim_product_child` / `dim_product_parent`。** 需要产品身份就 `ATTACH` 产品包读。广告包重建了这两张表且 schema 与内容都不同（20 列 vs 7 列，342 vs 521 行），这是跨模块 join 断裂的根因。

**6.4 来源标注统一用 `value_origin` 列**，取值 `direct` / `derived` / `constructed`。这列**只用于内部对账，不上屏**。

**6.5 时间口径。** 日、周、30 天、月度、活动周期各自保留正式统计口径，不强制折算成同一周期（方案 §6 明确要求）。历史区间与基准日对齐 2026-08-03。

**6.6 数据性质与数据状态的统一表达（V6，借自 V5）。** `value_origin` 是库里的列、不上屏；上屏用下面两套固定词表，全站统一，不各模块自造说法：

| 数据性质 | 什么时候用 |
| --- | --- |
| 真实 | 直接来自客户提供的数据 |
| 推导 | 由真实数据按明确规则算出 |
| 模拟 | Demo 构造 |
| 混合 | 同一个数里既有真实也有构造成分 |

| 数据状态 | 什么时候用 |
| --- | --- |
| 正常 / 加载中 / 空结果 | 常规三态 |
| 过期 | 数据比基准日旧到影响判断 |
| 缺失 | 该有值但没有 |
| 待确认 | 阈值、算法或口径客户还没确认 |
| 失败 | 计算或取数出错 |

映射关系：`direct → 真实`、`derived → 推导`、`constructed → 模拟`，一个对象同时含多种来源时用 `混合`。映射发生在读取边界，页面只拿到中文词。

这两套词表同时解决两件事：构造数据能被诚实标出而不泄露枚举名；全站对"这个数可信到什么程度"只有一种说法。**语义色只服务这两套词表，不做装饰**，并且不能只靠颜色表达——同时给文字或形状。

## 8. 模块接口与独立替换保证

每个页面后续都会反复改。所以外壳和模块之间只允许一条窄接口，并且必须满足下面七条——任一条不成立，改一个模块就会牵动别人。

### 8.1 后端自注册：一个模块只有一个入口文件

`modules/<模块名>/module.py` 是外壳唯一读的文件，其余业务文件由它自己 import：

```python
MODULE = {
    "id": "keyword",              # 必须等于目录名
    "label": "关键词分析",
    "api_version": 1,             # 外壳按这个判断兼容性
    "pages": [                    # 页面清单，外壳据此生成导航
        {"id": "kw-overview", "label": "关键词动态与机会总览"},
        {"id": "kw-market",   "label": "市场关键词库与单词深研"},
        {"id": "kw-child",    "label": "子 ASIN 关键词盘点"},
    ],
    "routes": {                   # 资源名 -> 处理函数，外壳挂到 /api/keyword/<资源名>
        "terms":  handle_terms,
        "term":   handle_term,     # 带路径参数的写成 term/<id>
        "meta":   handle_meta,
    },
    "params": PARAMS,             # kw.* 参数声明，含 (下限, 上限, 步长)
    "db": DB_PATH,                # 只读 SQLite 路径，从 core/paths.py 取
    "invalidate": clear_caches,   # 可选：外壳热重载时调它清本模块缓存
    "tasks": TASKS,               # 可选：可运行任务，见下
}
```

**`tasks`：可运行任务声明（可选）。** 外壳的任务面板（槽位 6）读这个，自己不含任何清单。
模块**不要自己做任务触发入口或 agent 交互 UI** —— 那是外壳的活（契约第 9 节）。

```python
TASKS = [
    {
        "id": "forecast-90d",
        "label": "重跑 90 天需求预测",
        "needs": "object",        # 需要页面上先选中一个对象；省略则无对象也能跑
        "run": "run",             # 本模块 routes 里的一个资源名
        "hint": "读最近 730 天历史，重新判断缺货扭曲与活动影响",
    },
]
```

`run` 指向的处理函数返回 `{"run": {...}, "steps": [...]}`：

- `run`：`run_id` / `object_id` / `data_as_of` / `status` / `model_version`。`status` 用
  6.6 的状态词表（`完成` 之外的值会被面板标成失败）
- `steps`：每步 `label` / `detail` / `status` / `duration_ms` / `sources[]`。
  **`sources` 必须是中文数据源名**，`fact_*` 这类库内表名不上屏（G9）。
  `duration_ms` 是真实耗时，面板显示的是各步之和 —— 不要拿它表达别的东西

参照实现：`modules/sample/module.py` 的 `handle_run` + `MODULE["tasks"]`。

**`agents`：本模块拥有的 Agent 声明（可选）。** Agent 配置页读这个。

```python
MODULE["agents"] = [
    {
        "id": "demand-forecast",
        "label": "需求预测",
        "owner": "inventory",          # 必须等于本模块 id
        "status": "未接通",            # 未接通 | 已接通 | 设计待拍 | 待声明
        "model_version": None,
        "trigger": ["weekly", "manual", "priority"],
        "judges": [...],               # Agent 不可替代的判断（普通代码做不了的）
        "computed": [...],             # 确定性算术，留在工作台，不进 Agent
        "needs": [...],                # 必填上下文，缺一项就不该开跑
        "outputs": [...],              # 产物，中文描述，不写表名（G9）
        "thresholds": ["inv.safety_days_override", ...],   # 指向本模块 params 的键
        "contract": "01-方案与数据需求/07-预测Agent接口契约.md",
        "note": "...",
    },
]
```

三条硬要求，门禁 G25 逐条核：

1. **`thresholds` 只能写真实存在的参数键。** 写错一个字母，Agent 配置页上那一项
   静默消失 —— 不报错、不留痕，客户以为这个门槛不能调。
2. **`judges` 与 `computed` 的分界照 07 契约 §0 切**：Agent 判断需求，
   工作台算下游。算术留在工作台，阈值才能改完立刻重算；塞进 Agent 就得重跑才生效。
3. **没拍定的字段留空数组，不要编。** 把未定的判断写成看起来定了的样子比留空更坏 ——
   下游会照着实现，等真契约出来已经错了一轮。

**不要在模块里自建阈值存储或 Agent 配置界面。** 阈值的唯一真相来源是
`MODULE["params"]`，存档由外壳负责（`shell.js` 的 `PARAM_STORE`）；
配置界面是 Agent 配置模块的事。

未认领的 Agent 暂存在 `modules/agentcfg/registry_seed.py`，认领就是把那一项
整块搬进自己的 `MODULE["agents"]` 再从登记表删掉。G25 会报还剩几项没认领。

`registry.py` 扫 `modules/*/module.py`、import、读 `MODULE`，然后自动生成路由、导航、参数面板。**新增或删除一个模块，外壳一行代码都不用改。**

### 8.2 前端自注册：动态 import，不进任何清单

`web/modules/<模块名>.js` 是 ES module。ES module 的顶层作用域天然不是全局，所以模块内的
`let` / `const` 不会和别人撞名；要守的是**不往 `window` / `globalThis` 挂任何东西**
（旧两个 demo 都是裸脚本，`$` `el` `S` `pc` `load` `renderList` `renderScope` 七个名字直接对撞）。
只导出下面这些：

```js
export const id = "keyword";
export const apiVersion = 1;
export const filters = [ /* 声明式筛选项，由外壳渲染 */ ];
export function mount(root, ctx) { /* root 是外壳给的容器 */ }
export function render(state) { /* 状态变化时重绘 */ }
export function unmount() { /* 卸载时清掉自己的定时器与监听 */ }
```

外壳先请求 `/api/modules`（`registry.py` 的发现结果），再对每个 id 动态 `import("./modules/" + id + ".js")`。页面清单来自后端的 `MODULE["pages"]`，前端不重复声明，避免两处不一致。

`$`、`el`、数字与百分比格式化、浮层、抽屉一律从 `ctx` 取，不要自己实现。现有两个模块各写了一份浮层，合并时会互相抢"当前打开的是谁"。

### 8.3 状态隔离

模块只能读写 `state.modules.<模块名>` 这棵子树。跨模块共享的上下文（站点、时间范围、当前选中对象、生效筛选）由外壳持有，模块**只读**，要改走 `ctx.setShared(patch)`。模块不得直接读另一个模块的 state 子树。

### 8.4 故障隔离：一个模块崩了不能拖垮全站

- 后端：`registry.py` 逐模块 try/except 包住 import 与每个 handler。import 失败的模块标 `degraded` 并从导航里降级显示，其余模块照常服务；handler 抛异常只返回该模块的错误载荷，不返回堆栈到浏览器。
- 前端：动态 `import()` 与 `mount()` 都包 try/catch，失败时在该模块的容器里渲染一个占位状态，外壳导航和其他模块不受影响。

判据：把任意一个模块的 `module.py` 改成语法错误，服务仍能启动，其余页面仍能打开。

### 8.5 模块之间禁止互相 import

`modules/keyword/` 不得 import `modules/ads/` 下的任何东西，反之同理。跨模块需要对方的结果时，走对方声明的对外输出（方案 §5，落在数据层或经外壳传递），不走代码依赖。

这条是"随时替换任一模块"能成立的根本原因：一旦互相 import，改 A 就要回归 B。

### 8.6 单模块可独立加载

支持只加载一个模块跑起来，用于开发和验证：

```bash
WORKBENCH_MODULES=keyword /usr/bin/python3 start.py restart
```

未列出的模块不 import、不出现在导航里。不传这个环境变量时加载全部。

### 8.7 改完怎么生效

- **前端（`web/` 下的 js/css/html）**：静态文件每次请求重读，刷新页面即生效，不用重启。
- **后端（`modules/` 下的 .py）**：Python 模块不会自动重载。`registry.py` 在开发模式下比对该模块目录的 mtime，只 `importlib.reload` 这一个模块的子树并调它的 `invalidate()` 清缓存，其他模块不动。热重载是尽力而为，行为可疑时以 `start.py restart` 为准。
- **`core/` 下的改动**：一律重启。

这也是为什么模块内的缓存必须能从 `invalidate()` 一次清干净——散落各处的 `lru_cache` 会让热重载读到旧值，那种 bug 很难查。

### 8.8 URL 即状态：路由与详情模型（V6，借自 V5）

当前两个 demo **没有路由、没有 hash、没有 history**：选中对象只活在内存里，刷新就丢，也没法把某个对象的页面发给同事。V6 采纳 V5 的做法——**URL 承载状态**，可解析可反解析，来回往返不丢信息。

物理路径而非查询参数承载"看哪一页、看哪个对象"：

```text
/inventory                       模块总览
/inventory/<child_asin>          单对象详情
/inventory/scope                 同模块的第二个页面（subview）
/keyword/<term_id>
/competitor/<rival_id>
/ads/classification              subview
/ads/asins/<child_asin>          subview + 对象
```

模块要提供两个纯函数（无副作用、可单测）：

```js
export function pathFor({ page, subview, objectId }) { /* → 字符串 */ }
export function parsePath(segments) { /* → { page, subview, objectId } */ }
```

外壳负责其余部分：`history.pushState` / 前进后退、把筛选与排序快照进 URL 查询串、返回时恢复筛选、选中对象和滚动位置。模块不自己碰 `history`、不自己读 `location`。

详情与抽屉用统一模型，不各页自造：详情是 `{ kind, id }`（`kind` 取模块自己声明的对象类型），抽屉是 `{ kind, id }` 或 `null`。同一时刻最多一个详情、一个抽屉。

对模块的具体要求：

- 每个页面和每个可下钻对象都必须有一个可直接访问的 URL；
- 参数（`kw.*` / `cmp.*` 等）走查询串，对象身份走路径段，两者不混；
- 对象 id 用 `encodeURIComponent` 编码，解码失败时回退原值不抛异常。

## 9. AI 交互窗口的接口

AI 能力由独立的 Agent 服务提供，外壳统一挂载交互窗口并反向代理请求。模块**不实现对话 UI、不直连 Agent**，只声明三件事：

1. **上下文**：当前对象、生效筛选、时间范围——这三样必须与主视图同步，AI 看到的和用户看到的一致；
2. **落点**：Agent 返回的结论渲染在页面哪个位置；
3. **依据定位**：点击 AI 给的依据时，反查并高亮页面上对应的哪个数据元素。

同一页面只允许一个 AI 入口。AI 建议不得渲染成已执行的动作。AI 结论不能代替数据关系——页面的关键结论必须能脱离 AI 文本被独立读懂（法则五）。

## 11. 禁止清单

结构类：

- 不自建 `index.html` / `app.css` / `server.py` / 端口 / token 定义；
- 不改外壳任何文件（`core/`、`web/index.html`、`web/shell.js`、`web/tokens.css`、`web/base.css`）；需要外壳加能力就提出来，不要就地改；
- 不 import 其他模块的代码，也不读其他模块的 state 子树；
- 不占用 `/api/meta`，不使用无前缀的参数键；
- 不在样式里写 `#id` 或裸元素选择器；
- 不在 JS 里声明全局变量。

信息设计类（全局原则 §10）：

- 未定义业务问题就默认生成四张 KPI 卡；
- 把每个字段包成独立圆角卡片；
- 为填满版面生成没有决策价值的图表；
- 用自然语言建议列表代替稳定的比较表格；
- 用 AI 结论代替可追溯依据；
- 同一页面多个 AI 入口；
- 在客户未确认前自行生成阈值、算法、口径或因果结论——未确认的要标出来，不要伪装成精确判断。

文案类（这几条是前两个模块返工付过学费的）：

- **防御性与免责表述一律不写进界面**：「不作为判断依据」「一次只能选一种粒度」「阈值均待客户确认」「P1 阶段…P2 实现」这类整句删除，口径限制记进数据缺口文档；
- **内部枚举值绝不上屏**：`can_absorb` / `cannot_absorb` / `direct` / `derived` / `constructed` / `report_month_total` 这类库里的叫法必须映射成中文成品文案，映射发生在读取边界，不在页面里做；
- 方法说明（怎么算的）收进 ⓘ 点开的浮层，不写成正文一行字；
- 两个数相等不要分两句报（不写「54 个对象，其中 54 个本期有数据」）。

工程类（这几条踩过且测试抓不到）：

- flex/grid 子项要能收缩必须显式给 `min-width:0` / `min-height:0`，grid 轨道用 `minmax(0,1fr)` 而非 `1fr`；
- 全局加 `[hidden]{display:none!important}`；判断显隐要查 `getComputedStyle().display` + `getBoundingClientRect()` + `elementFromPoint()` 三者，不能只查 `.hidden` 属性；
- 回归门禁必须打在**真有那个特征的对象**上。跑在一个既无异常也无缺口的对象上却报「0 条 / 0 根」还打勾，比没有门禁更糟。
