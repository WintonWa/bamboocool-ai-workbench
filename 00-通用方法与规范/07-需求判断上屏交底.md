## 3. 五个必须照做的点

### 3.1 回落必须一眼看出来

用 `is_agent` 分支。**不要把两种来源画成一样。**
没有判断的对象只有一个回测分数，画成和判断一样会让运营以为 342 个对象都被判断过了。

建议：`origin_label` 直接上屏（「Agent 判断」/「统计口径」）。
Agent 那种再带 `跑于 <created_at 前16位> · <trigger_label>`，回落那种不带时间。

### 3.2 语气沿用你已有的 `tone`，不要另立一套

你的结论带已经在用 `data-tone="alert|warn|good"`，CSS 也已经按它上色。
需求判断**复用同一套取值**，但 `forecast_judgment` 的 factor **不带 `tone` 字段**，
要你自己按下表加（后端故意不给：这是显示层判断，不是数据）：

| state | tone |
| --- | --- |
| `重度扭曲` | `alert` |
| `轻度扭曲` | `warn` |
| `衰退` | `warn` |
| 其余全部 | 不加 |

**方向不要用 tone 表达。** 屏幕上已经显示 `+4.00%` / `−5.00%`，符号本身就是方向。
给「淡季 −5%」标警示色是错的 —— 淡季不是问题，是季节。手写 state→颜色表迟早和数字打架，
出现「标红的 +3%」。

这三行是判断，你有异议就提，别默默改成另一套。

### 3.3 `impact_pct` 是小数，NULL 要和 0 区分

`0.04` 是 **+4.00%**，乘 100 再显示。

`null` 表示 **Agent 判断不出**，不是 0。实测真模型在 `B0B3LM36WB` 的生命周期上给了 null ——
它没有硬凑一个数，这个诚实要在屏幕上留住。建议 null 显示 `—`，0 显示 `0.00%`。
两者画成一样，就把「判断不出」和「判断为无影响」混成一件事了。

### 3.4 `factor` 是英文码值，一个字都不许上屏

用 `label`（已经是中文：缺货扭曲 / 站内活动 / 生命周期 / 广告投放 / 季节性）。
`stockout_distortion` 这种出现在屏幕上会被门禁 G9 抓。
`numbers` 里的键也是英文码值，同理 —— 那份数据是给交叉核对用的，不是给人看的。

### 3.5 别在模块里另做一个 Agent 触发入口

契约第 9 节：**任务触发是外壳任务面板的活，模块不自己做。**

你现在结论带上那个 `<button data-task="inv-verdict">进行产品分析</button>`
**只有标记、没有处理逻辑**（我查过，没有任何地方监听它）。三条路选一条：

1. 删掉它，运营从右缘的「任务」手柄开面板运行 —— 最合契约
2. 让它只负责**打开任务面板**，不自己发请求
3. 留着但接成直接调 `/api/inventory/run-forecast-judgment` —— **不建议**，
   这样就有了两个 Agent 入口，执行过程、失败提示、运行中状态都要再实现一份

`MODULE["tasks"]` 已经声明好了（`id: forecast-judgment`，`label: 重跑需求判断`），
任务面板会自动列出来，不需要你写任何触发代码。

### 5.1 `impact_pct = null` 不能靠某个活对象来验

这条是写这份交底时实测踩到的，值得你知道：

**产出方是 LLM，同一个对象跑两次可能给出不同的结果。** 实测 `B0B3LM36WB` 的生命周期
在 08:05 和 08:11 两次跑都给了 `null`（诚实地表示判断不出），08:13 那次却给了 `0.0`。
两者都合契约。

所以**不要在门禁或验收里写「`B0B3LM36WB` 的生命周期是 null」** —— 今天成立，
重跑一次就不成立了，而这种失败看起来像你的代码坏了。

验 null 渲染请用**临时造的一行**（往库里插一条 `impact_pct = NULL` 的 factor，看完删掉），
或者直接在前端用一个假对象过一遍。判据不变：`null` 显示 `—`，`0` 显示 `0.00%`，
两者视觉必须可区分 —— 「判断不出」和「判断为无影响」是两件事。

要重跑判断（会真调 LLM，约 16 秒）：

```
curl "http://127.0.0.1:18820/api/inventory/run-forecast-judgment?object=B0CBPXNC1M"
```

## 6. 你可能会踩的两个坑

**`summary` 在回落形状里是 `null`。** 直接往 DOM 塞会显示 "null"。

**同一天可以重跑多次。** 台账不设 `is_latest`，读取端已经按解析后的时刻取最晚
（`created_at` 有带 `+08:00` 和不带两种格式，字符串比会把带 Z 的判成前一天，
**更新的判断被更旧的盖掉且界面上没有任何症状**）。你只读 `forecast.judgment()` 的返回值，
不要自己再查库排序。
