### C01 · 盘点 state 究竟是规则结果还是 Agent 判断

- 当前事实：工作台已能确定性算出五个 state；Agent 登记又把“该不该动”定义为 Agent 核心判断。

- 不选择的代价：不拍板就无法设计正确的输入、验证和展示身份，现有答案锁定也无法安全拆除。
- 实施成本：中，改契约、输入桥、校验器和展示身份。

### C03 · `product_lifecycle` 是运营目标还是模型判断

- 编号 / 优先级 / 状态：`C03` / P1 / `needs_decision`
- 当前事实：字段出现在关键词 goal 和预测语义中；登记表把生命周期判断列为需求预测 Agent 的不可替代产出，但当前关键词桥把它当既有输入。
- 冲突双方：运营设定的阶段目标属于 committed plan；模型根据走势判断的生命周期属于 agent judgment。现有同名字段无法区分。
- 业务影响：预测与关键词可能互读答案，运营目标也可能被误当客观阶段。
- 推荐方向：拆为 `operator_lifecycle_goal` 与 `agent_lifecycle_judgment`，保留各自版本和 run_id；旧字段在迁移前标 `needs_decision`。
- 不选择的代价：预测与关键词之间会持续发生隐性答案回流，也无法尊重运营明确设定的目标。
- 实施成本：中高，跨产品、库存和关键词契约。
- 证据：`registry_seed.py:28-66`；`keyword_agent_facts.py:167-207`；关键词 schema。

### C05 · 广告 B0 判断归 Agent 还是确定性规则

### C07 · 是否保留兼容 `/api/agent/run`

### C08 · 库存总体分析与运营总览是否值得作为 Agent
