# 统一数据边界审计 · 执行摘要

审计日期：2026-09-02  
审计范围：产品与库存、广告、关键词、竞品四个主线模块；工作台读取层；Agent 输入桥、Runner、sidecar 与运行记录页。  
审计方式：只读代码、构建脚本与 SQLite 实际值；没有联网，没有使用归档目录作为事实来源。

## 一页概览

当前主线实际引用 **12 个 SQLite、175 张表**：5 个业务数据包（产品、广告、广告扩展、关键词、竞品），1 个工作台图表缓存，4 个正式或历史 Agent sidecar，1 个竞品 V2 sidecar，1 个关键词 Loop 状态库。另有关键词正式结果库和台账路径已经写进代码，但文件尚不存在，因此没有伪装成“活跃且有结果”的数据库计入表数。

现状不是简单的“事实库 + Agent 结果库”。产品包、广告扩展包、关键词包、竞品包都混入了不同程度的规则判断或预烤答案；工作台和 Agent 又各自选择其中一部分读取。来源字段 `direct / derived / constructed` 无法解决这个问题：`constructed` 既可能是合法的模拟历史事实，也可能是必须禁读的预制诊断；`derived` 既可能是中立均值，也可能已经把风险结论说完。

目标架构应固定为：

```text
实体/历史事实/当前观察 ─┐
已承诺计划 ────────────┼→ 确定性特征 → Agent 输入桥 → completed Agent run
外部可观察事实 ─────────┘                              ↓
工作台事实区 ← 事实/特征/规则结果              工作台 Agent 区
运营确认/修改/拒绝 → human_action_store → 执行与复盘
fixture 与 Demo seed run 永不进入上述正式读取链
```

## P0 问题

1. **库存盘点 Agent 被钉了答案。** 输入桥把工作台算出的五个 `expected_state` 直接交给 Agent，校验器要求 Agent 输出逐项相等。它当前只能改写措辞和排序，不是在独立判断。
2. **关键词没有正式 Agent 结果时读取基础包里的预烤答案。** 五张判断表被构建脚本明示为 Agent 输出点，当前均随基础包发布；正式结果库不存在时，六个 GET 路由回落基础包并继续读取这些表。正式关键词桥虽避开五表，却又读取 `fact_keyword_child_absorb` 的断货日、补货量、损失量、置信度，以及 `product_lifecycle`。
3. **产品预测快照仍作为无 Agent 结果时的页面答案。** 当前需求预测 Runner 的输入桥本身已经较干净，但页面在无完整 run 时回落 `fact_child_forecast_daily`；同时仍有可达的旧 `/api/agent/run` 链直接读取预烤预测、库存投影和补货建议。
4. **广告工作台 context 仍混入旧判断层。** 新广告 Runner 已经避开大部分 `ext_*` 结论表，但工作台 `build_context()` 仍读取目标约束、关键词匹配、竞品压力、结构问题；`handle_decide()` 还会从预烤任务、诊断和建议恢复交接内容。
5. **上游 run 与部分结果的发布条件不统一。** 广告桥读取库存 sidecar 时只排除 `model_version='seed'`，没有 completed 状态、截止日或 context 校验；广告 sidecar 现有 completed 运行中有少于八个输出点的记录，读取层仍会返回其部分 points。

## 模块成熟度

- **最接近目标：竞品 V2。** 观察库只读，模型输入会清除 `value_origin`、场景表和历史判断表；结果原子写入 V2 sidecar，页面只取 completed run，并校验 context hash。基础包里仍有 11 张 V1 判断表，应隔离，但主页面已经不读它们。
- **接近目标：需求预测当前 Runner。** `loadDemandForecastFacts()` 使用显式 allow-list，拒绝预烤预测、需求还原、生命周期阶段和预计效应字段；问题集中在页面 fallback、旧兼容路由和事实包污染，而不是当前 Runner 输入。
- **部分接近：广告新 Runner。** 新 sidecar、证据目录和九个输出点方向正确；输入桥仍有 `preset_uplift`、推荐预算/流量损失估计与上游 run 校验问题，工作台 context/决定接口仍读旧判断。
- **未达到目标：关键词。** Smoke 与正式 Runner 是两条链；Smoke 只产运行态不发布结果，正式链强制全量且未成功发布，页面实际靠基础包预烤判断运行。
- **未达到独立判断：库存盘点。** 原子落库已具备，但同一性门禁让 Agent 成为文案器。

## 哪些构造数据可以保留

模拟的产品关系、历史销量、历史广告表现、当前库存、活动排期、采购单和外部可观察快照，可以保留在 Demo 的事实/计划层，前提是语义角色与来源分别标记。确定性均值、差值、聚合与变化量可以保留在 feature store。预制风险、预测、生命周期阶段、断货日、诊断、机会、优先级、理由、置信度和建议只能进入 fixture，或写成带真实 `run_id`、明确 `demo_seed` 身份的独立 seed run；不能继续留在正式观察库并作为 fallback。
