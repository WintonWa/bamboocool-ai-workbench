How the system works
01

固定场景 · 真实执行

角色与目标

这是一个面向子 ASIN 销量、库存与补货判断的本地 Pi Agent Demo。目标不是模拟聊天，而是展示一条真实发生的九步业务工具链。

342个子 ASIN
730天逐日历史
90天未来推演
02

先认清对象，再开始计算

确认业务对象

Agent 先确认子 ASIN、父体关系、生命周期、尺码与演示画像。任意输入都会透明路由到一个完整样本，映射关系会被明确告知。

对象边界
子 ASIN 级预测，不把父体汇总当作单品事实。
样本边界
五类完整场景用于稳定演示，不伪装成客户专属预测。
访问边界
工具只读，不修改数据库，也不执行运营动作。
03

Tool 03 · Audit

审计逐日历史

预测前先检查 730 天逐日销量的覆盖、缺失和异常。日期窗口、数据来源与质量提示都会进入可见的执行摘要。

  • 历史覆盖逐日检查
  • 异常与缺失明确提示
  • 数据口径保留来源
04

先纠偏，再预测

还原真实需求

缺货会压低表面销量，促销会放大短期需求。Agent 会在可解释范围内还原这些失真，再把结果交给后续预测步骤。

观察销量→识别失真→还原需求
05

计划不是事实，影响需要估计

评估经营驱动

价格、广告、活动与生命周期信号用于解释未来变化，但它们仍是 Demo 输入或派生判断，不会被写成客户原始事实。

价格计划信号
广告投入变化
促销事件影响
阶段生命周期
06

Model-derived · 90 days

形成逐日预测

三个候选模型通过滚动验证后，输出未来 90 天逐日预测。页面展示 P10、P50、P90 三个口径，并始终标记为模型派生结果。

保守P10 基准P50 压力P90
07

Demand meets supply

推演库存三场景

库存快照、在途计划和逐日预测会被放进基准、压力、改善三种场景。结果给出风险日期与库存承接能力，而不是单一的“够或不够”。

基准

按 P50 需求观察主要风险。

压力

用更高需求检验供给韧性。

改善

纳入补货与经营调整后的路径。

08

建议必须带着边界

给出补货建议

Agent 会给出建议数量、风险日期和依据。它们用于演示决策链路，不直接构成真实采购承诺。

建议不是一个孤立数字，而是“需求假设 × 供给现状 × 风险容忍度”的结果。
