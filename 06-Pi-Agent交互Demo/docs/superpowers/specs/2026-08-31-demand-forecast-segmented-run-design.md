# 需求预测 Agent 分段运行设计

日期：2026-08-31  
状态：已确认，待实施  
依据：`01-方案与数据需求/12-需求预测Agent职责修订.md`、`01-方案与数据需求/13-需求预测Agent分段运行需求.md`

## 1. 目标与边界

本次只解决一件事：把一次约 107 秒、运行中完全不可见的需求预测，改成可实时观察的真实过程。

不改变 `12` 号文恢复的职责边界：模型仍直接产出未来 90 天逐日 `p10 / p50 / p90` 和五项需求判断，工作台继续计算库存余额、覆盖、断货、缺口与补货。分段只能按时间窗切，不能改成“模型给形状参数、代码展开 90 天”。

本轮不判断预测数字准不准：

- `baseline_units` 继续允许为 `null`；
- 不做因子乘回基线重建 `p50`；
- 不定义重建容差；
- 不新增逐日因子分解。

## 2. 方案选择

采用“分步落库 + 状态查询”，不采用纯 SSE。

原因：运行状态需要在刷新、断线和失败后仍可追踪；当前工作台到 Agent 的调用链仍以完整 JSON 为主，纯 SSE 会破坏兼容性。SSE 与落库并行虽然完整，但本轮没有必要承担双协议复杂度。

现有同步入口 `POST /api/agent/demand-forecast` 保持兼容；新增只读状态入口，供消费方按子 ASIN 或 `run_id` 查询当前运行和步骤。

## 3. 运行生命周期

### 3.1 开始

模型调用前先分配 `run_id`，并立即插入 `fact_child_forecast_agent_run`：

- `status = 'running'`；
- `created_at` 为真实开始时刻，带 `+08:00`；
- `completed_at` 暂空；
- 尚未产生的 `confidence`、`confidence_reason`、`judgment_summary` 暂空；
- `prev_run_id` 指向该对象上一次 `completed` run。

同一子 ASIN 同一时刻只允许一个 `running` run。重复请求返回现有 `run_id` 和当前状态，不再启动第二个模型会话。

### 3.2 运行中

每一步使用独立短事务更新，不在模型运行期间持有 SQLite 写事务：

1. 调用模型前写入或更新步骤为 `加载中`，记录 `started_at`；
2. 模型响应、工具执行和本步校验结束后更新为 `完成`，记录 `completed_at` 与真实 `duration_ms`；
3. 本步异常时更新为 `失败`，并把 run 内部状态更新为 `failed`。

第一项的步骤状态固定为 `加载中`，不能使用“运行中”或“进行中”。工作台现有状态词白名单只认 `加载中`，其他写法会被静默改成 `完成`。

`duration_ms` 从 `session.prompt()` 调用前开始，到该轮模型响应及工具校验完成后结束。它必须包含模型耗时，不能只计算 SQLite 查询或工具函数内部的几毫秒。

### 3.3 成功发布

五项判断与六段逐日预测先保存在本次 Runner 内存中。只有以下门禁全部通过，才在一个最终事务中发布：

- 五项判断通过现有字段、词表与客观数字校验；
- 六段合并后恰好 90 行；
- 日期从 `data_as_of + 1` 连续 90 天，无重叠、无缺口；
- 每天满足 `0 ≤ p10 ≤ p50 ≤ p90`；
- 每一行均由模型在对应时间窗的工具调用中直接提交。

最终事务写入逐日表、判断表，更新 run 的判断字段、模型版本和 `status = 'completed'`，并写真实 `completed_at`。步骤此前已逐步落库，不需要在最终事务中重新伪造。

### 3.4 失败与中断

可捕获异常时：

- 当前步骤记为 `失败`；
- run 记为 `failed`；
- 写入简短错误摘要；
- 不写正式逐日结果和判断结果；
- 已完成步骤保留，便于回看故障发生位置。

进程被强制终止时，允许 run 暂留 `running`；读取端永远只把完整 `completed` run 当作页面预测来源，因此半截结果不会上屏。后续可增加陈旧运行恢复，但不属于本轮阻塞项。

客户端取消只断开等待，不主动停止 Agent。Agent 可继续运行并最终发布；状态库是实际运行状态的权威来源。

## 4. 分段策略

采用六个连续 15 天窗口：

| 段 | 日期索引 | 输出行数 |
| --- | --- | --- |
| 1 | 1–15 | 15 |
| 2 | 16–30 | 15 |
| 3 | 31–45 | 15 |
| 4 | 46–60 | 15 |
| 5 | 61–75 | 15 |
| 6 | 76–90 | 15 |

每段都向模型提供明确的开始日期、结束日期及该窗口的未来运营计划；模型直接调用同一个“提交逐日预测分段”工具，提交该窗口的 15 行 `p10 / p50 / p90 / baseline_units`。`baseline_units` 可以为 `null`。

工具逐段验证日期边界、行数和分位关系。前段结果通过后才进入下一段，不能并行生成，也不能由代码根据参数扩展。

## 5. 步骤模型

一次正常真实运行共有 12 个步骤：

1. 审计历史销量与缺货；
2. 分析历史需求影响项；
3. 读取未来运营计划；
4. 确认上架时长与承接背景；
5. 形成五类需求判断；
6. 生成第 1–15 天逐日预测；
7. 生成第 16–30 天逐日预测；
8. 生成第 31–45 天逐日预测；
9. 生成第 46–60 天逐日预测；
10. 生成第 61–75 天逐日预测；
11. 生成第 76–90 天逐日预测；
12. 校验并发布需求预测。

每一步都有中文 `label`、中文 `detail`、中文 `sources`、状态、开始时刻、结束时刻和真实耗时。内部工具码不进入面向页面的状态响应。

步骤状态只使用 `加载中 / 完成 / 失败` 三个词。

先以 15 天窗口真实运行。如果任一预测段超过 25 秒，改为九个 10 天窗口并重新测试。若完整运行墙钟超过 150 秒，停止继续细拆并向用户报告，再讨论模型或上下文策略。

## 6. 数据结构与兼容

### 6.1 run 表

沿用 `fact_child_forecast_agent_run`，支持：

- `running / completed / failed` 三态；
- 开始时即存在；
- `created_at` 与 `completed_at` 表达不同事件；
- 可选 `error_message` 保存失败摘要。

为兼容已有数据库，尚未产生的非关键文本字段可以先写空字符串，完成时更新；`completed_at` 在旧 NOT NULL 结构下可先写空字符串，不能用开始时刻冒充完成时刻。

run 表继续使用英文内部状态，不能把现有 `latest()` 的 `status='completed'` 过滤改成“按最新一条读取”。重跑期间页面必须继续显示上一次完整 Agent 结果，新的 `running` 或 `failed` run 不参与预测结果选择。

状态接口在读取边界把 run 内部状态映射为中文：

| run 表内部值 | 状态接口 `status` |
| --- | --- |
| `running` | `加载中` |
| `completed` | `完成` |
| `failed` | `失败` |

### 6.2 step 表

沿用 `fact_child_forecast_agent_step`，补充：

- `started_at`；
- `completed_at`；
- `加载中 / 完成 / 失败` 状态；
- 包含模型等待时间的 `duration_ms`。

迁移必须兼容已有 completed run，旧步骤缺少开始/结束时刻时允许为空。

### 6.3 正式结果表

`fact_child_forecast_agent_daily` 与 `fact_child_forecast_judgment_factor` 仍只存最终成功结果。运行过程不把半截 15 天分段写入正式逐日表。

## 7. 状态接口

新增只读接口，路径固定为：

```text
GET /api/agent/demand-forecast/status?childAsin=B0B3LM36WB
GET /api/agent/demand-forecast/status?runId=<run_id>
```

查询规则：

- 给 `runId` 时精确读取该次运行；
- 只给 `childAsin` 时，优先返回该对象当前 `running` run，否则返回最近一次运行状态；
- 两个参数都没有或对象不存在时返回明确的 `ok: false` 和中文 `error`。

成功响应形状固定为：

```json
{
  "ok": true,
  "run": {
    "run_id": "B0B3LM36WB-2026-08-03-4",
    "child_asin": "B0B3LM36WB",
    "status": "加载中",
    "created_at": "2026-08-31T11:10:00+08:00",
    "completed_at": null,
    "model_version": "deepseek/deepseek-v4-flash",
    "current_step": 7,
    "total_steps": 12,
    "error": null
  },
  "steps": [
    {
      "seq": 1,
      "label": "审计历史销量与缺货",
      "detail": "已审计730天历史",
      "status": "完成",
      "started_at": "2026-08-31T11:10:00+08:00",
      "completed_at": "2026-08-31T11:10:08+08:00",
      "duration_ms": 8123,
      "sources": ["历史逐日销量", "历史逐日可售库存"]
    },
    {
      "seq": 7,
      "label": "生成第16–30天逐日预测",
      "detail": "正在生成2026-08-19至2026-09-02的15天预测",
      "status": "加载中",
      "started_at": "2026-08-31T11:10:52+08:00",
      "completed_at": null,
      "duration_ms": null,
      "sources": ["需求判断", "未来运营计划"]
    }
  ]
}
```

状态接口中的 `run.status` 和 `steps[].status` 均只使用 `加载中 / 完成 / 失败`。它独立回答本次运行是否成功，失败时同时返回：

- `run.error`：run 级中文失败摘要；
- 失败步骤的 `detail`：该步骤的中文失败原因；
- 已经完成的步骤：原样保留。

查询参数无效或找不到运行时的响应形状固定为：

```json
{
  "ok": false,
  "run": null,
  "steps": [],
  "error": "没有找到这次需求预测运行"
}
```

响应字段含义：

- `run_id`、`child_asin`、`status`；
- `created_at`、`completed_at`；
- 当前步骤序号、总步骤数；
- 已开始步骤列表；
- 每步中文标签、中文详情、中文来源、状态、真实耗时；
- 失败时的中文错误摘要。

不返回模型内部思维链、SQL、文件路径、工具原始 JSON 或内部工具码。

同步 POST 的最终响应形状保持现有兼容：成功仍返回 `ok / run_id / child_asin / model_version / steps / daily_written / factors_written / errors`。

## 8. 页面接缝说明

当前工作台 `shell.js` 已有真实运行指示、取消等待和重复点击提示，但代码仍将整个任务挂在一次 `await fetch()` 上，尚未轮询步骤。Agent 侧完成本设计后，数据库与状态接口将具备真实进度；页面要逐条展示，仍需消费状态接口或由工作台后端代理该接口。

本次实施不修改工作台页面、取消交互、置信度展示或空基线展示。

## 9. 测试与验收

自动化测试覆盖：

1. run 在模型调用前已存在且为 `running`；
2. 步骤开始、完成、失败可以被另一个只读连接实时读到；
3. 模型运行期间没有长写事务；
4. 六段日期边界正确，合并后恰好 90 天；
5. 少段、重叠、缺日、分位倒挂均不能发布；
6. 失败 run 不会成为工作台最新预测；
7. 重复请求不会为同一对象启动两个 running run；
8. 状态接口不泄漏工具码、SQL、文件路径或思维过程；
9. 原有同步 POST、工作台读取和库存计算保持兼容；
10. `baseline_units = null` 原样保留。

真实 Pi 冒烟以 `B0B3LM36WB` 执行，记录：

- 完整墙钟时长；
- 每步真实 `duration_ms`；
- 每个预测窗口耗时；
- 最长单步是否不超过 25 秒；
- 步骤耗时合计是否与墙钟时长同一量级；
- 完整墙钟是否超过 150 秒。

若最长步骤超过 25 秒，切换为 10 天窗口后复测。若完整墙钟超过 150 秒，不继续无上限细拆，向用户报告后再决定是否调整模型或上下文。
