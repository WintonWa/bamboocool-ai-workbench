# 关键词 Agent Loop Smoke 接入设计

日期：2026-08-31  
状态：已实施
范围：`09-工作台` 关键词模块右侧任务窗口

## 1. 目标

在工作台关键词页面右侧的统一任务窗口中，点击“运行关键词分析”后真实启动本机 Pi Agent，并逐步展示它读取首批数据、调用模型、提交工具结果的过程。

当前 Demo 只验收 Agent Loop 能真实启动和完成一个小批次，不要求生成完整 A–E 五张输出表，也不要求发布业务结果。

## 2. 不变边界

- 现有正式选库门禁保持不变：只有 business manifest 与正式账本均为 `completed`、run/context/参数一致时，六个关键词业务路由才读取 `keyword_agent_current.sqlite`。
- Loop Smoke 不创建、不覆盖、不伪造 `keyword_agent_current.sqlite`。
- Loop Smoke 不把正式 manifest 改成 `completed`，也不向正式结果账本写入一条假完成记录。
- 页面正文继续读取 base 数据；任务窗口只展示运行过程，不渲染或注入半份业务结论。
- 已有 `keyword-all-2026-08-03-003.recovery.sqlite` 保留为上次完整链路未完成时的恢复证据，本功能不修改它。

## 3. 采用方案

采用“独立持久化运行态 + 工作台轮询”，不复用正式发布账本，也不增加 SSE。

原因：

1. 与库存页已经验证过的任务窗口机制一致；
2. 页面刷新、浏览器断线或触发请求提前结束后，仍能恢复最近一次任务过程；
3. 运行状态不会污染正式结果状态；
4. 保留未来将 Smoke 扩展为完整 A–E 运行的接口空间。

## 4. 组件与职责

### 4.1 关键词 Agent 服务

Agent 服务新增关键词 Loop Smoke 任务接口：

```text
POST /api/agent/keyword/loop-runs
GET  /api/agent/keyword/loop-runs/status
```

POST 立即分配 `task_id` 并在后台启动真实 Pi，不等待模型运行结束。相同时间只允许一个关键词 Loop Smoke 任务运行；重复点击返回当前任务，不并发启动第二个模型会话。

GET 返回最近一次任务的运行头和步骤，供工作台轮询。

### 4.2 独立运行态库

运行态写入：

```text
09-工作台/modules/keyword/derived/keyword_agent_loop_state.sqlite
```

该库只保存任务过程，不保存业务判断表。至少包含：

- `task_id`、状态、模型版本、创建/结束时间、安全错误信息；
- 顺序步骤、步骤状态、中文说明、中文数据来源、更新时间；
- 当前步骤、总步骤和已接受候选数。

法定任务状态为 `running / completed / failed`，在工作台边界映射为“加载中 / 完成 / 失败”。

### 4.3 工作台关键词模块

关键词模块在 `MODULE["tasks"]` 声明一个模块级任务：

```text
运行关键词分析
```

任务不要求选择子 ASIN。在关键词三个页面中的任意一个页面打开右侧任务窗口，都可以启动同一个关键词模块 Agent。

模块新增两个转接路由：

```text
GET /api/keyword/run-agent-loop
GET /api/keyword/agent-loop-status
```

触发路由转调 Agent 服务的 POST；状态路由读取 Agent 服务的 GET，并转成外壳既有 `{run, steps}` 形状。工作台不直接运行 LLM。

### 4.4 工作台外壳

继续复用库存页已经实现的任务面板和轮询逻辑：

- 触发请求不等待；
- 每 1.5 秒轮询状态路由；
- 每次按真实状态重画步骤；
- 取消只停止浏览器等待，不声称停止 Agent；
- 终态展示“Loop 演示完成，未发布业务结果”或安全失败原因。

外壳只需允许成功终态的 `run.message` 上屏，避免“运行完成”被误解为五张业务表已经完成。该变化适用于所有任务，并只在服务端实际返回 message 时显示。

## 5. 单次 Smoke 运行链

一次任务严格按以下顺序执行：

1. 冻结分析范围与六项判断参数；
2. 从允许输入表读取首批市场候选；
3. 创建真实 Pi 会话，只开放市场事件提交工具；
4. 模型判断首批候选并调用一次工具；
5. 工具门禁接受结果并记录产出数量；
6. 在 Demo 边界正常结束任务，明确标记“未发布业务结果”。

首批候选数量固定为 20。单次模型请求最多等待 60 秒，不自动重试；这样右侧窗口可观察真实运行，同时避免 Demo 再次占用十几分钟。

本功能可通过 `BAMBOO_KEYWORD_MODEL=provider/model-id` 显式选择已配置模型；未设置时优先使用本机已配置的 `xiaoyao/gpt-5.6-luna`，本机没有该模型才回落 Pi 当前默认模型。模型不可用、余额不足或超时时，任务进入 `failed`，步骤中显示安全中文原因，不泄漏密钥、原始响应体或堆栈。

## 7. 并发与失败处理

- 只有 `running` 任务才占互斥锁；终态任务不阻塞下一次点击。
- 任务进程退出但账本仍为 `running` 时，状态读取端将其收敛为 `failed`，避免永久加载中。
- Agent 服务不可达时，工作台返回结构完整的失败状态，而不是 HTTP 500。
- 模型没有调用指定工具、工具参数被门禁拒绝、模型超时或子进程异常，均落为失败步骤。
- 无论成功或失败，都不触碰正式 current、manifest 和结果账本。

## 8. 验收

1. 关键词模块右侧任务窗口出现“运行关键词分析”；
2. 点击后 25 秒内出现新的真实 `run_id`；
3. 任务窗口按顺序显示冻结范围、读取候选、Pi 分析、工具接受和 Demo 收口；
4. 至少发生一次真实 Pi 模型请求；
5. 成功时明确显示“Loop 演示完成，未发布业务结果”；
6. 失败时显示安全中文原因，并允许再次运行；
7. 刷新页面可以读回最近一次步骤；
8. `keyword_agent_current.sqlite` 不因 Smoke 产生或变化；
9. 正式半份 recovery 仍被六路由拒绝；
10. 关键词 Agent roundtrip 16 条继续全部通过；
11. 工作台任务面板和关键词模块新增测试全部通过。
