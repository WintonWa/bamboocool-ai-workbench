## 0. 分界：Agent 判什么，工作台算什么

一把尺子（`00-通用方法与规范/08-Agent需求与数据契约要则.md`）：

> **这条数据在真实业务里、Agent 跑之前，存在吗？**
> 存在 → 输入。不存在、要判出来 → 产出，且页面展示的必须是这一份。

| Agent 判（三段） | 工作台算（确定性） |
| --- | --- |
| 预测销量能不能直接当预投基数，要不要按去年同期与市场走向调整、调多少 | 月度预测聚合到配色组 |
| 未来已排的 BD/LD 会把这一轮下单推到什么水平 | 现行 Excel 口径复刻（对拍基线） |
| 这一轮尺码占比该怎么拆 | 盒→条→吨换算 |
| | 达成率与 70% 达标判定 |
| | 闲置量与资金占用 |
| | 尺码历史占比基线 |
| | 时间链条六个日期 |
| | 与现行口径的差额 |

算术留在工作台，阈值才能在参数面板上改完立刻重算；塞进 Agent 就得重跑才生效。

## 1. 判断对象

**一个配色组 = 款号 × 组合**，共 57 个，`group_id` 形如 `TH22AM-097|7D`。

这与库存模块不同：库存最小对象是子 ASIN（342 个），预投是配色组。
客户原话（01:04:51）：「预投它是根据就是你可以理解为一个配色组去预投，就是一个颜色组合去预投」。

尺码在这里不是对象，是**被拆分的比例**——第三段判断就是判它。

## 2. 输入：Agent 可以读什么

全部是「Agent 跑之前真实业务里就存在」的东西：

| 输入 | 来源 |
| --- | --- |
| 该组各子体近 730 天逐日销量（含去年同期同月） | 产品包 `fact_child_sales_daily` |
| 该组各子体未来 90 天 p10/p50/p90 | 产品包 `fact_child_forecast_daily`（需求预测 Agent 的产出，对本 Agent 是上游事实） |
| 未来已排活动计划与折扣 | 产品包 `plan_child_promotion_daily` |
| 该组历史各轮预投数、下单数、达成率 | 预投包 `fact_preinvest_cycle` + `fact_preinvest_order_batch` |
| 该组尺码历史销量占比轨迹 | 预投包 `fact_preinvest_size_share` |
| 该组身份：单包条数、子体清单、生命周期 | 预投包 `dim_preinvest_group` + 产品包 `dim_product_child` |
| 时间链条各段天数 | 预投包 `dim_preinvest_leadtime` |
| 七个阈值 | **随请求传**，不从库里读（见 §5） |

### 2.1 禁止入参 —— 读了就等于把答案递给它照抄

| 禁读 | 为什么 |
| --- | --- |
| 工作台算出的**现行 Excel 口径预投量** | 这是要跟它对拍的另一方。喂进去 Agent 会向它收敛，对拍就失去意义 |
| 源表 `3.库存表` 的 `建议发货（2个月）`/`建议备货（4个月）`/`预投预计` 三列 | 口径不明的派生列。实测整数占比只有 2%（中位 4~7），不是盒数，最可能是存销比一类的比率 —— 客户没确认过它算的是什么，喂进去等于让 Agent 引用一个没人能解释的数 |
| 本模块算出的**达成率预判、闲置量、资金占用、折吨数** | 那些是 Agent 判完之后的下游 |
| 任何 `value_origin` 列 | 英文码值可能上屏（G9/G17），且直接告诉模型哪些数是构造的会改变它的行为 |

唯一例外：算与上一轮的差异时需要读上一次运行。**首次真跑必须显式降级为「无可比上一版」**，不许拿别的东西顶替。

## 3. 产出：三张表，逐列写死

改这里必须同步改 `agent_result.py`。**列名少一列，工作台按列名取值直接报错；多一列被忽略。**

### 3.1 `fact_preinvest_agent_run` —— 一次运行一行

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `run_id` | TEXT | 主键，由**写入端**盖章，不由工作台指定 |
| `group_id` | TEXT | `款号\|组合` |
| `run_date` | TEXT | `YYYY-MM-DD`，纯日期无格式歧义，取最新时用它粗筛 |
| `created_at` | TEXT | ISO 时间戳，**必须带时区偏移**（见 §4.2） |
| `status` | TEXT | 只能是 6.6 状态词表里的词：`完成`/`失败`/`加载中`/`空结果`/`过期`/`缺失`/`待确认`/`正常` |
| `model_version` | TEXT | 真实模型名 |
| `trigger` | TEXT | `monthly` / `manual` / `priority` |
| `target_sales_month` | TEXT | `YYYY-MM`，本轮预投对应的销售月 |
| `preinvest_units` | INTEGER | **本轮预投建议盒数**。判断不出就给 NULL，不要给 0 |
| `order_units` | INTEGER | 本轮下单量预判，用于算达成率预判。同样可 NULL |
| `confidence` | REAL | 0~1。**必须 Agent 自己判**，不许引用包里现成的置信度列 |
| `confidence_reason` | TEXT | 中文，为什么是这个确定程度 |

### 3.2 `fact_preinvest_agent_judgment` —— 一次运行三行（三段判断）

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `run_id` | TEXT | 对应 run |
| `group_id` | TEXT | 冗余，便于单表查 |
| `segment` | TEXT | **只能是 `demand` / `promotion` / `size` 三个值**，落词表外工作台显示「待确认」 |
| `adjust_units` | INTEGER | 这一段调了多少盒，带符号。瀑布图每一段的高度就是它 |
| `adjust_rate` | REAL | 相对基数的比例，可 NULL |
| `basis_cn` | TEXT | **中文依据一句**：维度 + 幅度 + 当前状态。不写结论以外的话 |
| `direction` | TEXT | `up` / `down` / `flat` |

段名与中文的对应（工作台侧词表，Agent 只写英文键）：

| `segment` | 中文 | 对应客户点名的判断 |
| --- | --- | --- |
| `demand` | 预投数量判断 | 「去年同期你是不是还做一些调整？那这个调整就很难说了」 |
| `promotion` | 下单数字判断 | 「明明他下个月是会安排一些 BD 或者 LD，而他没有把这些事考虑进去」 |
| `size` | 尺码拆分判断 | 「M 码、L 码、XL 码，它的销量也是动态波动的」 |

### 3.3 `fact_preinvest_agent_size_split` —— 一次运行 N 行（N = 该组尺码数）

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `run_id` `group_id` | TEXT | 同上 |
| `size` | TEXT | 必须命中该组在产品包里的尺码 |
| `share_suggested` | REAL | 建议占比，同一 run 内**各尺码之和应为 1** |
| `share_history` | REAL | Agent 读到的历史占比，回填便于对账 |
| `basis_cn` | TEXT | 中文依据 |

### 3.4 关于「不许照抄」的一条硬要求

`share_suggested` **不能等于** `share_history`（除非 Agent 明确判断本轮不该动，并在 `basis_cn` 里说明理由）。
直接照抄历史占比等于没有解决客户说的「尺码之间销量动态波动」那个问题。

## 4. 工作台侧的回落规则

### 4.1 逐情形（`agent_result.py` 逐条实现，页面必须都看得出来）

| 情形 | 页面表现 |
| --- | --- |
| 库不存在 | 整块「未接入」，不是空白 |
| 库有但判断表不齐 | 「未接入」+ 说明本次产出不完整（半份产出显式拒绝） |
| 台账无该配色组 | 该组 AI 列留空，其余照常 |
| 判断表缺行 | 同上 |
| 同组多次运行 | 取最新：`run_date` 粗筛 + 解析时刻选最晚 |
| 字段为 NULL | 显示「—」，**不填默认值** |
| `segment` 落词表外 | 显示「待确认」，不回落英文原值、也不静默空白 |

### 4.2 两条踩过的坑，写在这里免得重犯

**时间戳不能按字符串排。** 注入方给过两种 ISO 格式——`2026-08-30T22:56Z`（UTC）
和 `2026-08-31T06:22`（本地）。按字符串排会把实际更晚的判成更旧。
读取端已做宽容（两种都能正确排序），但**写入端要求统一带偏移**。

**绝不静默回落到现行 Excel 口径然后当成 AI 口径。** 那会让页面上的对拍差额变成 0
却看不出原因——无症状的错误比露馅的错误难查得多。

## 5. 阈值随请求传，不从库里读

工作台参数面板是阈值的唯一真相来源（契约 §8.1）。本 Agent 声明的三个门槛键：

| 键 | 默认 | 性质 |
| --- | --- | --- |
| `pre.achieve_rate_min` | 0.70 | 客户明确给的考核线 |
| `pre.safety_margin_rate` | 0.10 | 由客户举例「预计 100 盒投 110 盒」反推 |
| `pre.lead_days_total` | 75 | 客户口述「约两个半月」 |

另外四个「现行口径复刻」的窗口权重（`pre.w_3d/w_7d/w_15d/w_30d`）**不传给 Agent**——
那是对拍基线的参数，不是 Agent 的判断依据。
