## 1. 判断对象：配色组（款号 × 组合）

吴组长原话（01:04:51）：「预投它是根据就是你可以理解为一个配色组去预投，就是一个颜色组合去预投」。

产品包 `dim_product_child` 已经带 `style_no` / `combination` / `colorway` / `size`，
所以配色组能直接从 342 脊椎聚出来，**不需要引入第二套产品宇宙**（契约 G7/G8）：

| 层 | 数量 |
| --- | --- |
| 运营组 | 1（一组） |
| 运营 | 3（王倩倩 / 曾向锋 / 吴孙晟） |
| 款号 | 15 |
| **配色组（款号×组合）** | **57 ← 预投的最小判断对象** |
| 子 ASIN | 342（每组 3~8 个尺码） |
| 尺码 | 8（S/M/L/XL/XXL/XXXL/4XL/5XL） |

属性缺失：无款号 0 个、无组合 1 个、无配色 13 个、无尺码 1 个。

**这是与库存模块的根本区别**：库存最小对象是子 ASIN（342），预投最小对象是配色组（57）。
尺码在预投这里不是对象，是**被拆分的比例**——也就是吴组长说的第三个人为判断点。

## 2. 真实预投/下单历史：`一组6月月报.xlsx` 的「6月预投下单」

路径：`数据源/AI广告对接数据-总20260803/14.其他分析文件/2026年月报/6月/一组6月月报.xlsx`，sheet index 4。

列（20 列，第 12~15 列原表无表头）：

```
运营组 运营 一级分类 二级分类 款号 组合 条数 搭配
预投数 追加数 预投总数 [46175 46182 46189 46196] 总下单数 剩余数 预投比 单包条数 总条数
```

四个无名列是**日期序列号**，还原后是 `2026-06-02 / 06-09 / 06-16 / 06-23`
——即**一次预投对应四批周度下单**。这坐实了预投与下单是两个步骤（吴组长 01:02:19 确认）。

### 2.1 恒等式（机械核对，不靠列名猜）

| 恒等式 | 命中 |
| --- | --- |
| 预投总数 = 预投数 + 追加数 | 141 / 141 |
| 剩余数 = 预投总数 − 总下单数 | 141 / 141 |
| 总条数 = 预投总数 × 单包条数 | 140 / 141 |

### 2.2 ⚠️ 「预投比」这列的口径与吴组长口述的**不是同一个数**

- 表里的 `预投比` = **剩余数 ÷ 预投总数**（106 行逐位命中；另 35 行是 `#DIV/0!` 或空）
- 吴组长说的 70% 考核（01:01:44）= **总下单数 ÷ 预投总数**（只 2 行偶然命中）

两者互补：**达成率 = 1 − 预投比**。
本模块统一用「达成率」这个词，页面不出现「预投比」，避免同一个名字两个意思。

### 2.3 一组 6 月真实数字

141 个配色组行里**有一行是「合计」汇总行**（款号列写「合计」、组合列为空），
必须挡掉：它的预投 252,951 恰好等于上面所有真实行之和，不挡就把整组数字翻一倍。
这个错**没有症状**——达成率是比值，翻倍后仍然是 89.03%，一眼看不出来。
构建脚本已加两条判据（组合列为空 / 款号是汇总词）并把挡掉的行打印出来。

挡掉后：140 个真实配色组行，其中 106 个预投 > 0（另 34 个预投=0，原表显示 `#DIV/0!`）。

| 指标 | 值 |
| --- | --- |
| 预投合计 | **252,951 盒** |
| 下单合计 | **225,196 盒** |
| 闲置（预投−下单） | **27,755 盒** |
| 整组达成率 | **89.03%** |
| 达标（≥70%）配色组 | **74 / 106 = 69.8%**（32 个不达标） |
| 达成率中位数 | 97.6% |
| 加权平均单包条数 | 5.186 条/盒 |

252,951 盒这个量级与吴组长口述的「我们一个月销量也差不多 20~30 万袋」（01:00:59）
**吻合**——所以这轮预投就是对一个月销售期的，原先怀疑的口径歧义不存在，
那是汇总行重复计数造成的假象。

达成率分布（这张图直接上页面）：

```
[  0%, 30%)   17 组   █████████████████
[ 30%, 50%)    6 组   ██████
[ 50%, 70%)    9 组   █████████
[ 70%, 90%)    6 组   ██████
[ 90%,100%]   62 组   ██████████████████████████████████████████████████████████████
[     >100%]   6 组   ██████     ← 下单超过预投
```

形态很清楚：**要么几乎全用掉（62 组在 90% 以上），要么整批打水漂（17 组低于 30%）**，中间很少。
这说明偏差不是「普遍多投一点」，而是**少数配色组整批投错**——正好是 Agent 能拿分的地方。

### 2.4 已澄清：这轮预投对应一个月销售期

原先怀疑「预投合计对不上客户说的月销 20~30 万袋」，实际是**汇总行重复计数**造成的
（见 §2.3）。挡掉后 252,951 盒正好落在客户口述区间内，所以这轮预投就是**一个月**的。

页面仍然写「2026 年 6 月一轮」而不写「6 月一整月」——因为下单是分四批的
（06-02/09/16/23），说「一轮」比说「一个月」更贴近这张表真正描述的东西。

### 6.1 ⚠️ 已修正：最后三列不是盒数

`建议发货（2个月）` / `建议备货（4个月）` / `预投预计` 这三列**不是预投盒数**。
本文早先把 `预投预计` 写成「当前 Excel 算出来的预投建议值、是 AI 对拍的天然基线」，
那个判断是错的。实测（`probe_three_cols.py`）：

| 列 | 非零行 | **整数占比** | 中位 | 最大 | 判定 |
| --- | --- | --- | --- | --- | --- |
| 各月预投 / 补投（第 53~69 列） | 106~423 | **100%**（10 月 90%、11 月 88%） | 250~1200 | 46,000 | 盒数 ✓ |
| 翻单合计（第 70 列） | 315 | **100%** | 272 | 61,040 | 盒数 ✓ |
| 建议发货（2个月） | 748 | **2%** | 4.00 | 1,904 | 比率型 ✗ |
| 建议备货（4个月） | 761 | **2%** | 5.36 | 3,264 | 比率型 ✗ |
| 预投预计 | 772 | **2%** | 6.88 | 3,264 | 比率型 ✗ |

判据是**整数占比**：预投是按盒下给工厂的，必然是整数（实测各月预投列 100% 整数）。
这三列 98% 是长小数（最小 0.0052），量级集中在 3~10，且三列之间没有简单恒等式
（`预投预计 = 建议发货 + 建议备货` 只命中 6/753 行）。同一配色组某些尺码上三列
取值完全相同（如 4B 的 S 与 M 三列都是 3.35211267605634），说明它们是同一个公式
在不同参数下的三个结果，某些输入为 0 时退化成同一个值。

结合同表第 18 列子表头就叫「存销比」，这三列最可能是**存销比 / 可售月数**一类的
比率，而不是建议量。**精确口径要问客户**，本模块不用它们。

好在这个误判没有污染任何数字：现行 Excel 口径是本模块**自己从逐日销量算**的
（3/7/15/30 天加权），从来没读过这三列；用到的只有各月预投列（做逐月趋势），
那些是纯整数的真盒数。

⚠️ 这张表的预投数在同一配色组的多个尺码行上重复，直接求和会重复计数。
所以本模块**不拿它做金额汇总**，只用它看逐月趋势与填充覆盖。汇总一律用 §2 的月报表。

## 7. 单位与成本

`fact_unit_economics` 证实了销售单位：`unit_basis = sellable_unit_盒`，
且 `pack_size` 就是组合首位数字（4A→4 条，7D→7 条），57 组**无一缺失**。

| 项 | 值 | 来源 |
| --- | --- | --- |
| 单包条数 | 3 ~ 7 条/盒，一组加权平均 5.186 | 组合首位数字，产品包已派生 |
| 单盒成本 | 中位 56.70，区间 44.32 ~ 109.12 | `unit_cost`，27/57 组缺失，**币种客户未确认** |
| 面料换算锚点 | 30 万盒 ≈ 200 吨 | 吴组长 01:02:50 原话 |
| → 折算 | **666.7 g/盒**（= 128.6 g/条 × 5.186） | 由锚点反推 |
| → 闲置 27,755 盒 | **≈ 18.5 吨面料** | 上面两项相乘（逐行按各自单包条数折，不用平均） |

**「省多少钱」这一项必须标成估算。** 锚点只给了盒与吨，没给面料单价，
`unit_cost` 是成品成本不是面料成本。所以金额 = 闲置盒数 × 单盒成本 × 面料成本占比，
其中**面料成本占比是 Demo 预设参数（默认 0.35），客户未确认**，界面上按「待确认」标注。
主指标仍用**盒**与**吨**——那两个能一路追到客户自己的数字。

## 8. 现行做法（要复刻成对拍基线）

吴组长 00:55:54：「最近 3 天、最近 7 天、最近 15 天、最近 30 天的加权平均」
吴组长 00:59:27：「10 月份我预计他卖 100 盒……然后我可能就会投到 110 盒」→ 安全余量约 10%

⚠️ 两处未给：**四个窗口各占多少权重**、**安全余量到底几个点**。
所以做成可调参数（默认四窗口等权 0.25、安全余量 10%），界面标「口径待确认」，
不伪装成精确判断（契约 §11）。

另注：领星系统实际给的窗口列是 3/7/**14**/30 天，吴组长口述是 15 天。
本模块按口述的 15 天自己从逐日销量算，不用领星的 14 天列，两者差异记在这里。
