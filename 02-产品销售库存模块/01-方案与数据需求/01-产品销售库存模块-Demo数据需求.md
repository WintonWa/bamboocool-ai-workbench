# 产品销售库存模块 Demo 数据需求

更新时间：2026-08-29  
适用页面：异常总览、库存全览、单一子 ASIN 盘点  
用途：为客户可把玩的演示版反推数据结构、数据规模、计算结果和场景覆盖  
数据声明：本文中的规模、阈值、样例分类和结果均为 Demo 构造建议，不代表客户真实经营事实或正式算法

## 1. 结论先行

这个模块不能只准备一张“产品库存表”。要让三页真正可筛选、可下钻、可解释，至少需要五层数据：

1. 产品与业务分类维表；
2. 按日销售、活动、库存、在途、批次库龄和费用等事实数据；
3. 预测、库存余额、覆盖余缺和费用等派生结果；
4. 一个子 ASIN 可同时拥有多条的风险记录；
5. 数据时间、来源、质量、规则和计算版本等追溯信息。

推荐 Demo 使用一个美国站、一个重点品线，构造 **8 个父 ASIN、72 个子 ASIN、180 天历史销售、90 天未来预测、13 个周度盘点版本**。这个量足以形成有密度的父子产品列表、筛选组合和五类风险分布，同时仍然可以在前端以本地 JSON 或轻量数据库快速运行。

Demo 应把“业务链条是否完整”放在第一位，不追求预测和费用金额的真实准确性。所有构造原始数据标记为 `simulated`，所有计算结果标记为 `derived`，并保留生成批次、规则版本和数据截止时间。

### 2.3 访谈确认的业务事实

- 客户希望销售预测覆盖全部产品，不只覆盖头部产品；尾部库存和新品预测都是重要问题。
- BD/Deal 是统一销量预测的输入，不应形成与日常销量预测冲突的第二套预测；其目的首先是提供第三方参考，不要求第一版百分之百准确。
- 活动会被新增、调整或取消，因此活动必须有状态和版本，不能只保存一个静态日期。
- 日常折扣、BD 和大促都会影响需求；首期可以弱化常规季节性，但不能忽略活动日历。
- 运营需要直观看到库存和仓储压力，尤其是未来 3 至 7 天内即将跨入 180 天库龄的库存数量，并能定位到对应运营和产品。
- 冗余库存、尾部库存和资金占用需要形成风险；库存不足与断码也不能忽略。
- 风险阈值和预测参数应可配置并保留版本，Demo 可使用预设参数，但不得把预设说成客户正式标准。

## 3. 统一业务对象与计算主线

### 3.1 对象层级

```text
站点 / 品线
  └─ 产品族 / 款号
      └─ 父 ASIN（分组与汇总）
          └─ 子 ASIN（最小盘点与风险单元）
              ├─ 产品属性：颜色、尺码、组合、阶段、定位、负责人、售卖状态
              ├─ 按日销售与活动
              ├─ 位置 × 状态 × 批次库存
              ├─ 在途与预计可售事件
              ├─ 预测、库存余额、覆盖、余缺、库龄和费用
              └─ 盘点结果、风险记录与版本追溯
```

父 ASIN 只负责归属、折叠分组和汇总。所有正式库存状态、风险和承接能力必须落到子 ASIN。

### 3.2 统一计算链

```text
产品关系与分类
  + 按日销售
  + BD / Deal / 大促 / 日常折扣计划
  + 当前库存、在途、批次与费用
  + 规则与版本
        ↓
未来每日需求预测
        ↓
未来每日可用库存余额
        ↓
覆盖天数、缺口、余量、消化周期
        ↓
库龄、货值、资金占用、仓储费
        ↓
五类风险、严重程度、原因和库存承接能力
        ↓
异常总览 / 库存全览 / 单品盘点读取同一结果
```

| 临界库龄提醒 | 未来 3/7 天跨入 180 天的库存 | 批次入库日、盘点日、剩余量 | `days_to_180`、3/7 日临界量 |
| 仓储费分析 | 当前费、正常费、超龄费和压力 | 实际/模拟费用、费率、体积、销售、毛利 | 金额、构成、费销比、费毛利比 |
| 风险点与原因 | 同一子 ASIN 的全部风险 | 风险多值记录 | 严重度、排序分、原因、关键依据 |
| 盘点历史 | 风险新增、加重、减轻、解除 | 13 个周度盘点版本 | 前后变化和风险生命周期 |
| 查看依据 | 来源、时间、口径、规则、版本、缺失项 | 数据血缘与质量记录 | 结果到原始记录的引用 |
| 情景测算（推荐增强） | 临时调整 BD、ETA、安全库存、补货量 | 会话参数、正式基线结果 | 调整前后预测、余额、缺货日、覆盖 |
| 模拟 AI 解释（可选增强） | 针对当前子 ASIN 的结论、原因、不确定性 | 盘点结果、风险、证据引用、预置问答 | 可用模板生成，不要求真实大模型 |

### 4.4 全局状态和异常边界

Demo 不能只有“数据完整且结论成功”的理想状态。至少准备以下状态，并让页面说明哪些结论因此不可生成：

- 正常且无明显风险；
- 当前筛选无结果；
- 新品或历史不足，预测置信度低；
- 无活动计划；
- 活动已取消或刚修改，预测版本待更新；
- 在途存在但 ETA 未知；
- 总库存有量但可售口径异常；
- 产品定位或阶段缺失；
- 安全库存、交期或阈值使用 Demo 默认值；
- 某个数据源过期；
- 仓储费缺失，只能展示估算；
- 预测或盘点计算失败；
- 部分数据为模拟、部分为派生。

## 5. Demo 推荐数据规模

### 5.1 主体规模

| 对象 | 推荐规模 | 目的 |

| 颜色 | 6–8 个模拟值 | 支持服装变体辨识 |
| 尺码 | 5–6 个模拟值 | 支持同父体断码和变体差异 |

| 库存状态 | 可售、预留、不可售、待调仓、入库中、在途 | 覆盖可用性计算和状态结构 |

### 5.2 时间长度与记录量

| 数据 | 推荐时间/数量 | 预估记录量 |
| --- | --- | ---: |
| 按日销售 | 过去 180 天 | 12,960 行 |
| 未来需求预测 | 未来 90 天，每日基线和正式预测 | 12,960 行（两种情景） |
| 活动 | 历史 6 个月 + 未来 90 天，约 35–50 个事件 | 35–50 个事件；子 ASIN 关联约 150 行 |
| 当前库存快照 | 子 ASIN × 位置 × 实际存在状态 | 700–1,100 行 |
| 历史库存快照 | 过去 13 周，每周一次摘要 | 3,000–5,000 行 |
| 库存批次 | 每个子 ASIN 2–6 批 | 220–300 行 |
| 在途/入库/调仓事件 | 约 40% 子 ASIN 有 1–3 条 | 45–80 行 |
| 仓储费 | 过去 6 个结算月，按子 ASIN × 费类 | 600–900 行 |
| 每日库存投影 | 72 × 90 天 | 6,480 行 |
| 周度盘点结果 | 72 × 13 周 | 936 行 |
| 风险记录 | 每次盘点 0–3 条，当前约 70–100 条 | 历史约 700–1,200 行 |

总规模控制在约 5 万行结构化记录即可。对于前端 Demo，可以把列表摘要预聚合，详情页再按子 ASIN 懒加载明细，避免一次加载全部时间序列。

### 5.3 风险与状态分布

72 个子 ASIN 建议覆盖：

- 14 个健康或轻微波动对象；
- 10 个以库存不足为主；
- 10 个以超量备货为主；
- 8 个以库存可用性异常为主；
- 8 个以库龄风险为主；
- 6 个以仓储费压力为主；
- 10 个同时命中两到三类风险；
- 6 个数据不足、过期、ETA 未知或计算失败对象。

风险条数和风险产品数必须分别计算，因为一个子 ASIN 可以命中多类风险。严重程度建议约为 High 20%、Medium 45%、Low 35%，确保排序和分布图都有层次。

| `scenario_type` | 是 | baseline / official_with_events / what_if |
| `baseline_units` | 是 | 基础预测 |
| `trend_units` / `seasonality_units` | 是 | 组成项；首期季节性可为 0 或轻量 |
| `event_increment_units` | 是 | 活动增量 |
| `forecast_units` | 是 | 正式预测 |
| `lower_units` / `upper_units` | 是 | 预测区间 |
| `confidence_score` / `confidence_level` | 是 | 置信度 |
| `history_days_used` | 是 | 使用历史长度 |
| `linked_promotion_ids` | 否 | 活动引用 |

Demo 推荐可解释算法：加权 7/14/30 日平均 + 轻量趋势 + 活动增量；断货日不直接当低需求日。准确性不是验收目标，但同一输入应得到稳定、可重复的输出。

### 7.11 库存投影 `fact_inventory_projection_daily`

粒度：盘点运行 × 子 ASIN × 未来日期 × 库存范围。

建议字段：`projection_run_id`、`projection_date`、`child_asin`、`scope_type`、`opening_available_qty`、`forecast_demand_qty`、`confirmed_supply_qty`、`estimated_supply_qty`、`closing_available_qty`、`safety_stock_qty`、`shortage_qty`、`excess_qty`、`supply_event_ids`、`forecast_run_id`。

至少支持三种范围：

- `sellable_only`：仅当前可售；
- `sellable_plus_confirmed`：当前可售加确认能按时转可售的库存；
- `all_known`：包含 ETA 未确定或受限库存，仅作结构参考，不作为正式承接结论。

### 7.12 子 ASIN 盘点结果 `fact_inventory_assessment`

粒度：盘点运行 × 子 ASIN。

建议字段：

- 身份与版本：`assessment_id`、`child_asin`、`assessment_at`、`assessment_version`、`rule_set_id`、`forecast_run_id`、`projection_run_id`；
- 销售：`units_7d/14d/30d/90d`、`avg_daily_units_7d/30d`、`sales_trend`、`forecast_units_30d/90d`、`event_increment_90d`、`forecast_confidence`；
- 库存：`sellable_qty`、`restricted_qty`、`inbound_qty`、`total_known_qty`、`availability_rate`；
- 承接：`cover_days_sellable`、`cover_days_confirmed`、`stockout_date`、`safety_breach_date`、`shortage_qty_30d/90d`、`excess_qty`、`depletion_days`；
- 库龄与货值：`aged_qty_180_plus`、`aged_share_180_plus`、`qty_crossing_180_3d/7d`、`inventory_value`、`aged_inventory_value`、`excess_inventory_value`；
- 费用：`storage_fee_current_month`、`regular_storage_fee`、`aged_surcharge`、`storage_fee_sales_ratio`、`storage_fee_gross_profit_ratio`；
- 结论：`inventory_status`、`primary_risk_type`、`primary_risk_severity`、`capacity_level`、`capacity_extra_units_30d`、`result_summary`；
- 质量：通用治理字段和 `unavailable_outputs`。

### 7.13 风险记录 `fact_inventory_risk`

粒度：盘点结果 × 子 ASIN × 风险类型；不要把五类风险压成五个布尔字段。

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `risk_id` / `assessment_id` | 是 | 风险与盘点关系 |
| `child_asin` | 是 | 风险对象 |
| `risk_type` | 是 | shortage / overstock / availability / aging / storage_fee |
| `severity` | 是 | high / medium / low |
| `risk_score` | 是 | 排序分，Demo 规则可解释 |
| `risk_status` | 是 | new / worsened / unchanged / eased / resolved |
| `expected_start_at` / `expected_peak_at` | 否 | 风险时间 |
| `affected_quantity` / `affected_value` | 是 | 影响量与货值 |
| `reason_codes` | 是 | 结构化原因数组 |
| `reason_summary` | 是 | 短解释 |
| `evidence_refs` | 是 | 指向预测、快照、批次、费用和规则 |
| `previous_risk_id` | 否 | 风险生命周期 |

### 7.14 数据源运行与血缘

#### `fact_source_run`

记录 `source_batch_id`、来源、文件、Sheet、覆盖开始/结束日期、导入时间、行数、成功/失败、完整性、新鲜度、冲突数和错误摘要。

#### `fact_result_lineage`

粒度：派生结果字段 × 输入记录/规则。建议字段为 `result_table`、`result_id`、`result_field`、`input_table`、`input_record_id`、`rule_set_id`、`calculation_step`、`run_id`。

Demo 无需给每个日销量都做复杂血缘 UI，但至少要让一个明星子 ASIN 的主风险可以回指到预测版本、库存批次、供应事件和规则版本。

### 7.15 会话情景和可选 AI 内容

#### `fact_demo_scenario`

粒度：当前会话 × 子 ASIN × 情景版本。字段包括 `session_id`、`child_asin`、`scenario_version`、`base_assessment_id`、`bd_uplift_override`、`eta_override`、`safety_stock_override`、`supply_qty_override`、`created_at`、`is_saved`。

#### `demo_ai_insight`（可选）

无需接真实大模型。可为每个明星对象构造结论、时间程度、关键原因、建议方向、不确定性和 `evidence_refs`，再通过预置问题触发。AI 内容必须由盘点结果生成或引用，不能与表格数字脱节。

## 8. 核心派生指标与 Demo 计算口径

以下是可用于 Demo 的候选关系，不是客户正式算法。

| 指标 | Demo 候选计算 | 备注 |
| --- | --- | --- |
| 日均销量 | 有效销售日净销量 / 有效天数 | 断货与异常日单独处理 |
| 正式需求预测 | 基线预测 + 活动增量 | 按日输出，90 天累计 |
| 当前可用率 | 当前可售 / 当前已知总库存 | 分母需排除重复与共享未分配库存 |
| 未来可用库存 | 当前可售 - 累计预测 + 截至当日确认转可售量 | ETA 未知不进入正式余额 |
| 可售覆盖天数 | 当前可售 / 近期或预测日均需求 | 日均为 0 时显示不可计算/极高，不造伪值 |
| 确认库存覆盖天数 | 可售 + 按时确认供应对应的逐日余额 | 应用每日投影，不建议只做静态除法 |
| 缺货日 | 首个投影余额小于或等于 0 的日期 | 同时保留安全库存突破日 |
| 周期缺口 | 需求周期累计需求 + 安全库存 - 周期内可用库存 | 最小为 0 |
| 合理库存上限 | 目标覆盖天数 × 预测日均需求 | 目标覆盖由规则版本提供 |
| 超量库存 | 总可用库存 - 合理库存上限 | 最小为 0；展示位置构成 |
| 消化天数 | 可消化库存 / 预测日均需求 | 低销量对象要限制极端值并说明 |
| 库龄 | 盘点日 - 批次入库日 | Demo 使用剩余批次和 FIFO 预设 |
| 3/7 日临界量 | `0 < days_to_180 <= 3/7` 批次剩余量之和 | 访谈明确的重要展示 |
| 库存货值 | 剩余量 × 单位成本 | 按位置/状态/库龄可拆分 |
| 仓储费率 | 仓储费 / 净销售额 | 销售额为 0 时显示不可计算 |
| 仓储费毛利率 | 仓储费 / 毛利 | 毛利小于等于 0 时以特殊状态表达 |
| 承接能力 | 未来余额、缺口、活动需求和安全库存的规则映射 | 例如可承接/有限承接/不可承接；名称待确认 |
| 风险排序分 | 偏离程度、影响量/货值、时间紧迫度、费用/利润影响、阶段权重 | 分项要可解释，不用黑箱随机数 |

## 9. 数据生成原则

### 9.1 先构造故事，再生成噪声

每个明星子 ASIN 先定义场景、事件和期望结果，再反推销售、库存、批次和费用。其余产品可用参数化分布生成，但不能全是随机独立数，否则会出现“销量高却预测低”“批次数量与库存不一致”等穿帮。

### 9.2 保持跨表守恒

- 当前库存快照中的批次数量合计要与产品摘要一致；
- 各状态库存合计要与总库存一致；
- 预测累计值要等于每日预测求和；
- 正式预测要等于基线加活动增量；
- 库存投影必须按上一日余额连续滚动；
- 仓储费构成合计要等于总仓储费；
- 风险依据里的数量、日期和费用要能在详情数据中复核；
- 父体与范围汇总必须来自子 ASIN，不单独手填。

### 9.3 生成确定性

生成器使用固定随机种子，并输出 `dataset_version`、`seed`、`generated_at` 和期望场景清单。这样前端、测试和演示人员看到相同对象和相同结论。

### 9.4 真实感处理

- 销售使用周内波动、轻量趋势、活动抬升和少量异常日，不使用完全平滑直线；
- 首期常规季节性影响可弱化，与访谈一致；
- 服装变体体现同父体不同颜色/尺码销量和库存差异；
- 供应事件应有按时、延迟、取消、ETA 未知等状态；
- 费用和货值与库存量、体积、库龄保持方向一致；
- 页面所有构造对象使用虚构 ASIN、SKU、姓名和产品文案，避免被误认成客户事实。

## 10. 可简化和必须保留的边界

### 10.1 Demo 可以简化

- 销量预测使用可解释的加权平均、趋势和活动增量，不训练正式模型；
- 仓储费可同时提供“模拟账单值”和简化估算值，不复刻 Amazon 全部收费规则；
- 历史批次可直接构造剩余量，不回放完整采购、入库、出库流水；
- 共享库存只做 1–2 个示例，不建设完整多店分摊引擎；
- 货币只使用 USD，保留 `currency` 和 `fx_rate` 字段即可；
- 一个站点、一个重点品线即可，多站点只保留扩展字段；
- AI 助手可以使用预置问答和结构化模板；
- 情景测算默认只在会话中预览，不做审批和真正保存；
- 补货量和最晚发货日可作为增强项，没有客户正式交期和安全库存规则时只能标为 Demo 估算。

### 10.2 Demo 不能省略

- 子 ASIN 作为最小判断单元、父体只聚合；
- 三页共用同一盘点结果；
- 一个子 ASIN 支持多风险；
- 销售真实段、未来预测段、活动事件和库存投影使用一致日期轴；
- 位置和状态分开建模；
- 当前可售与总库存不能混为一谈；
- 在途必须有 ETA/预计可售日和确定性；
- 活动必须有状态与版本；
- 批次入库日必须支持 3/7 日跨 180 天提醒；
- 风险必须包含类型、严重度、时间、原因和依据；
- 数据时间、来源类型、质量状态、规则版本和计算版本可见；
- 模拟数据不得标记为客户真实数据；
- 无法计算时显示原因，不能用随机精确数补空。

## 11. 实施建议顺序

1. 先落产品、负责人、位置、状态、规则等维表和枚举；
2. 为 6 个明星对象手工定义场景参数和期望结果；
3. 生成 72 个子 ASIN 的 180 天销售与活动事件；
4. 生成当前库存、批次和供应事件，并做数量守恒；
5. 生成基线与含活动的 90 天需求预测；
6. 逐日生成库存余额、覆盖、余缺、库龄和费用；
7. 生成 13 个周度盘点和风险生命周期；
8. 从盘点结果生成异常总览与库存全览聚合，不另造摘要；
9. 输出前端友好的索引 JSON 和按子 ASIN 拆分的详情 JSON；
10. 用验收规则自动检查关键故事和跨表一致性。

建议数据文件按以下层次组织：

```text
demo-data/
  metadata.json
  dimensions/
  raw-simulated/
  derived/
  page-indexes/
  scenarios/
  validation/
```

## 12. 验收清单

### 12.1 数据完整性

- [ ] 8 个父 ASIN、72 个子 ASIN 均有稳定唯一标识和父子关系。
- [ ] 每个子 ASIN 均有负责人、阶段、定位、售卖状态；故意缺失对象有质量标记。
- [ ] 所有销售、活动、库存、批次、供应、费用均可关联到子 ASIN。
- [ ] 销售至少覆盖连续 180 天，正式预测连续覆盖未来 90 天。
- [ ] 位置和状态为两个独立维度，至少覆盖四类位置和六类状态。
- [ ] 批次剩余量与当前库存快照在约定口径下守恒。
- [ ] 活动包含计划、批准、活动中、取消和完成等不同状态及至少一个版本变更。
- [ ] 供应事件包含按时、延迟、取消和 ETA 未知。
- [ ] 仓储费包含正常费和超龄附加费，并能拆到来源库存。

### 12.2 计算一致性

- [ ] 每日正式预测等于基线与活动增量的约定组合。
- [ ] 90 天累计预测等于每日预测求和。
- [ ] 库存余额曲线逐日连续，供应只在预计转可售日增加。
- [ ] ETA 未知的在途不进入正式可用库存。
- [ ] 覆盖天数、缺货日、缺口和超量结果能从明细复算。
- [ ] `qty_crossing_180_3d/7d` 能从批次日期和剩余量复算。
- [ ] 库存货值、仓储费构成和比例的分子分母一致。
- [ ] 父体和范围汇总来自子 ASIN；非加总指标没有错误求和或简单平均。
- [ ] 每条风险都能引用至少一个预测/库存/批次/费用结果和一个规则版本。

### 12.3 场景覆盖

- [ ] 五类风险均至少有 High、Medium、Low 示例。
- [ ] 至少 10 个子 ASIN 同时命中两类以上风险。
- [ ] 有同父体下“多数健康、单一尺码缺货”的示例。
- [ ] 有 BD 导致需求和库存结论改变的示例。
- [ ] 有活动取消后预测与风险版本变化的示例。
- [ ] 有未来 3 天和 7 天跨 180 天的批次。
- [ ] 有总库存高但可售低的可用性异常。
- [ ] 有风险新增、加重、减轻和解除的盘点历史。
- [ ] 有新品历史不足、ETA 未知、数据过期和计算失败状态。

### 12.4 页面与交互

- [ ] 异常总览切换风险分类时，摘要、图表和列表读取同一筛选上下文。
- [ ] 库存全览筛选后，范围摘要、结构和父子产品区同步更新。
- [ ] 父体可展开查看子 ASIN，筛选状态下可直接显示子 ASIN。
- [ ] 点击风险产品能进入对应子 ASIN 并定位到相关板块。
- [ ] 从详情返回能恢复筛选、排序、父体展开和滚动位置。
- [ ] 需求与库存图共同日期轴，悬停日期同步高亮。
- [ ] 切换基线/含活动预测时，库存余额和缺货结论同步变化或明确保持正式版本。
- [ ] 数据依据能显示模拟/派生状态、截止时间、质量、规则和计算版本。
- [ ] 情景测算能显示调整前后，不覆盖正式盘点结果。
- [ ] 无结果、缺失、过期和失败状态都有明确解释。

### 12.5 演示可信度

- [ ] 所有 ASIN、SKU、产品名、运营姓名均为虚构或经授权使用。
- [ ] 页面明确标注“演示模拟数据”，不伪装成客户经营事实。
- [ ] 风险标签旁能看到时间、数量或差距，不只靠颜色。
- [ ] 演示人员能在 5 秒内找到最高风险对象，在 15 秒内说明类型、时间和主因。
- [ ] 至少 6 个明星对象有固定演示脚本和自动校验期望值。
- [ ] 固定随机种子后重复生成数据，关键对象和关键结果不变化。

## 13. 仍待真实项目确认、Demo 暂用预设的事项

- 产品跟踪表的正式字段、产品阶段和产品定位分类；
- 销量以订单、发货还是净销量为正式口径；
- 预测历史窗口、断货修正、活动增量和更新频率；
- 安全库存、合理覆盖周期、缺货和超量阈值；
- 各库存位置和状态何时计入“可用库存”；
- 采购、运输、入仓和调仓的正式交期；
- 库存批次消耗规则和正式库龄分段；
- 180 天及其他收费节点、正常/超龄费率和风险阈值；
- 仓储费压力使用销售额、毛利或其他经营指标作为分母；
